# Active work packets

Only deliberately started, non-trivial work belongs here.

Each file must be copied from `docs/templates/FEATURE_WORK_PACKET.md` and kept current enough that another agent can continue without relying on chat history.

GitHub issues and pull requests own dynamic work status. Active packets provide implementation context and evidence; they are not a second backlog or project board.

Before opening a new packet, check that the work is not already represented by an active packet or pull request. Keep at most the deliberately active initiatives here. When the controlling issue is closed as completed, move the packet to `../completed/` in the closing PR or the next documentation-only cleanup and record the final merge, CI, deployment and acceptance evidence. A closed master issue must not remain represented as active work.
