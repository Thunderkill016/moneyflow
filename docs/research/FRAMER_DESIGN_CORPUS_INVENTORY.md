# Framer public design corpus inventory

**Status:** dated source inventory

## Scope and completeness boundary

Framer publishes design knowledge across several public surfaces rather than one category:

- Blog — Tutorials
- Blog — Inspiration
- Academy courses and topic lessons
- Product Design surface
- Brand and trademark guidelines
- Help articles related to pages, layout, responsive behavior, publishing, accessibility, SEO and site structure
- Guides and developer component documentation

The Blog category pages use a dynamic `Load more articles` boundary, and Academy topic pages may expose only the currently loaded lesson set to crawlers. This inventory records every design item discoverable through the public category/topic pages and official indexed pages on the access date. It does not claim that private, deleted, unindexed or client-rendered-only items were read.

Tool-operation tutorials are inventoried at topic and lesson level where available. They inform implementation awareness but do not become MoneyFlow architecture or design authority.

## Product Design surface

Official Framer Design material covers:

- freeform design canvas;
- AI-assisted layout exploration and iteration;
- responsive phone/tablet/desktop views;
- components and reusable assets;
- interaction and animation previews;
- moving from exploratory Design Pages to published Web Pages;
- preserving designer control while using AI.

MoneyFlow takeaway: AI can generate options and accelerate exploration, but owner selection, semantic authority, code review and evidence remain required.

## Brand guidelines

Official Framer brand guidelines were reviewed as an example of identity governance:

- logo and wordmark usage;
- clear space and minimum size;
- color and background application;
- trademark boundaries;
- approved assets;

MoneyFlow applies the governance pattern, not Framer's identity assets or visual language.

## Help, pages and site structure

Relevant official help material includes:

- Web Pages, CMS Pages and Design Pages as separate purposes;
- Web Pages defining the public sitemap;
- Design Pages as private exploration canvases;
- automatically generated `sitemap.xml`;
- URL and redirect management;
- publishing and production boundaries;
- SEO and metadata behavior;
- site readability and content structure.

MoneyFlow takeaway: exploration artifacts and production routes must remain clearly separated, and release evidence must refer to the actual deployed route and exact commit.

## Guides and developer documentation

The public Guides surface currently marks several practical guides as `Coming soon`. Existing developer documentation covers:

- component introduction and examples;
- asset sharing;
- auto-sizing;
- property controls;
- component reference;
- overrides;
- plugin and server APIs.

MoneyFlow takeaway: component contracts need explicit purpose, sizing, properties, examples and ownership, but Framer's runtime APIs are not adopted into the Next.js application.
