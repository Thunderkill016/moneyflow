- Status impact: MoneyFlow already computes a deterministic tenant-scoped trusted-through boundary. This PR wires that existing contract into the single bounded dashboard read and presents a compact trusted/limited/blocked state with at most one next maintenance action; it does not broaden the truth boundary to external bank/provider completeness.

Playwright official emulation guidance was used to harden the browser proof. Final review also checked PostgreSQL official `CREATE FUNCTION` documentation: `SECURITY INVOKER` is the default, and `CREATE OR REPLACE FUNCTION` retains ownership/permissions while assigning other properties from the replacement command; pgTAP remains the executable ACL/search-path/RLS proof.

Current `src/lib/dashboard-performance-contract.test.ts` rejects that shape by requiring exactly one dashboard RPC and no direct table read. The issue/work packet were revised before implementation; trust is composed inside PostgreSQL `get_dashboard_bundle` instead of adding network fan-out.
