## Why this slice exists

PR #337 established that many semantic-looking classes emitted by shared UI primitives have no unconditional owner in the production bundle. Current `globals.css` already defines aliases such as `--background`, `--foreground`, `--primary`, `--border`, `--input` and `--ring`, backed by the canonical MoneyFlow `--mf-*` roles. The missing link is Tailwind v4 registration: plain CSS variables do not themselves cause semantic utilities to exist.

Official Tailwind documentation states that `@theme` variables determine which utility classes exist and that `--color-*` theme variables create color utilities. Official shadcn Tailwind v4 guidance uses `@theme inline` to map semantic CSS variables into that namespace.

## Selected implementation

The active CSS entry registers semantic color theme variables by reference only. There are no hard-coded replacement colors in the bridge. `muted` intentionally reuses the existing secondary surface alias because MoneyFlow currently has no separate `--muted` alias, while `muted-foreground` retains its existing dedicated alias.

The exact number of newly owned classes is deliberately not claimed yet. The #337 gate and a clean production build must determine that after the branch can run against current `main`.
