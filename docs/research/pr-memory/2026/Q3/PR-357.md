## The lesson worth keeping: a fix can be complete and still not reach the user

Two of the four fixes looked done and were not, and in both cases a passing test
suite said otherwise.

**PP-12.** The primitive was corrected, but four consumer CSS modules set their own
dialog height through `.dialog.dialog` — specificity (0,2,0) against the primitive's
(0,1,0). Add/edit transaction, transfer, account and the planning dialogs therefore
stayed on `dvh`, including "Thêm & tài khoản", which is the surface the owner actually
reported. The test asserted `!dialog.includes("dvh")` against the two primitive files
only, so it stayed green while the reported bug remained. It now scans every dialog
surface.

**PP-16.** The parser was corrected, but `account-reconciliation-page.tsx` kept its
own `\D` strip. Because the shared formatter had *stopped* visibly rewriting the
field, the mismatch there became invisible rather than merely wrong — a strictly worse
state than before the fix, in a field that feeds a reconciliation difference. The
single-owner guard named three files and missed it; it now sweeps all twelve
consumers.

Both are the same failure: a source-string test that checks the file the author was
thinking about rather than every file the behaviour lives in.

## Authority precedence caught the same way

The seven-day condition also lived in `docs/product/PRINCIPLES.md`, which this
repository's own source precedence ranks **above** a work packet. Withdrawing it in
the packet alone would have left the requirement authoritative and the withdrawal
cosmetic.
