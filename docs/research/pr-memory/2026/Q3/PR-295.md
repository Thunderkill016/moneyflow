## Trigger

The protected Secret history scan fetches every branch/tag and scans `--all`. Draft PR #292 introduced a client-side Supabase publishable key in an isolated Penpot bridge prototype. Gitleaks classified the value under its generic API-key rule and consequently blocked unrelated PRs #293 and #294.

## Decision

Supabase's official API-key documentation classifies `sb_publishable_…` as low-privilege and safe for web pages, mobile/desktop apps, CLIs, GitHub Actions and public source. The repository already uses exact `.gitleaksignore` fingerprints for reviewed browser-safe publishable keys. Gitleaks upstream documents exact-fingerprint ignore entries as the narrow exception mechanism.

Add exactly one fingerprint for this historical finding. Do not reveal the key value, disable a rule, allowlist a path, rewrite history or perform a provider operation.
