# PR #490 — fix(ui): keep a nine-digit report total inside its cell

- Date: 2026-08-27
- Change class: Class 1 — one CSS Module rule gains a selector. No TypeScript, schema, migration, RPC, RLS, provider or dependency change; no ledger mutation.
- Affected capability or project boundary: money presentation inside the `/reports` period summary, via `src/components/money-value.module.css`.
- Status impact: candidate until merged. It restores `main` to green; no capability changes.
- Lifecycle impact: none. This is a defect fix ahead of the registered slice, and PR #489 is blocked behind it and will need a rebase.
- Why it takes priority: `main` is red. The cross-device audit reports `financial-value-overflowed` on `/reports` at tablet-landscape — `"+ 15.000.000 ₫"` painting about 197px inside a 177px box and spilling over the neighbouring cell, at P1 severity.
- Root cause, and the limit was always there: `.summary` in `secondary-layout.module.css` is `repeat(auto-fit, minmax(min(100%, 190px), 1fr))`, so a cell at that viewport carries a 177px content box after 16px padding and a 1px border each side. A nine-digit VND value at the default money scale does not fit it. Nothing about the grid changed.
- Why it appeared now, and this is mine: PR #487 stopped the demo dating its salary in a past month. Before that the demo's month income was 0 ₫, so this figure never rendered at full width and the overflow could not occur. The audit did not catch it inside #487 because `classify` selected no UI audit for that change — a docs-and-library diff — so the gate that would have caught it never ran on that head.
- Verified as pre-existing on `main` rather than assumed: the failing spec was run against `main` with no other change and reproduces the identical overflow, which is what rules out PR #489 as the cause.
- Changed: `[data-slot="report-metrics"] .value` joins the existing `ledger-summary` / `timeline-summary` selector rather than receiving a rule of its own. That rule exists for exactly this situation and its comment already states the principle — keep complete amounts on one line and use a denser, readable scale instead of wrapping or clipping financial data inside summary and row owners. Money is neither wrapped nor clipped here; the complete amount stays on one line at the denser scale.
- Verified: both previously failing audit specs run locally against `chromium-tablet-landscape` — `responsive.audit.spec.ts` "reports stays usable" and `rich-state.responsive.audit.spec.ts` "reports-populated-money remains usable", 1 passed each. Plus `test` (1191 pass), `lint`, `check:css-ownership`, `check:knowledge`, `test:ci-policy`.
- Remaining: one audit failure this does not explain. `safety-review-states.audit.spec.ts` on `webkit-iphone` fails on a missing `Duyệt giao dịch` heading in the Inbox review dialog. I checked whether PR #487 could have caused it — `sampleCandidates` in `candidate-store.ts` pins its own `occurredOn: "2026-07-12"` and does not use the transaction fixture, so the Inbox seed is unaffected by that change. WebKit also crashes locally on that spec with an internal error during `page.goto`, so it could not be reproduced here to diagnose. Reported rather than claimed fixed.

- Snapshot update: not applicable. No capability, architecture, security, operations or verification truth changes; the board records the red `main` and the ordering against PR #489.
