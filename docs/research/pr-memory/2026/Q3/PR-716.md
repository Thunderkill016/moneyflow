# PR #716 — Kind filter + folded search inside the account register

- Date: 2026-09-25
- Change class: doctor projects Class 3 off the `account-detail` path
  keyword (`auth-and-account-deletion` heuristic); actual scope is a
  bounded presentational filter — no schema, no migration, no server
  action, no RLS surface. CI lanes per doctor: verify + browser smoke +
  cross-device UI audit + codeql; database false.
- Affected capability or project boundary: `/accounts/[accountId]`
  register (`src/components/account-detail-page.tsx` + CSS module) and
  the register domain module `src/lib/account-register.ts`.
- Status impact: the "no search/filter inside an account's register"
  gap from the account-surface comparison is closed. Remaining
  deferred gaps (credit-card lifecycle, per-account trends/export,
  institution logos, sync/forecast) are untouched and each still needs
  its own spec/owner decision.
- Changed:
  - `filterAccountRegisterEntries(entries, { kind, query })` in
    `src/lib/account-register.ts` — narrows by `transaction.kind`
    (`all | income | expense | transfer`) and a diacritic-folded query
    built with `normalizeSearchText` over note, payee, category, split
    category lines and the transfer counterparty name.
  - Toolbar row inside the register panel, only rendered when the
    register has entries: labeled search field + segmented kind buttons
    (`Tất cả / Khoản chi / Khoản thu / Chuyển tiền`, `aria-pressed`,
    44px targets), same recipe and token set as the transactions
    toolbar (`searchControl`, `kindFilter`, `kindButton`).
  - Meta line `Đang hiển thị N/M giao dịch` + `Xoá lọc` appears only
    while a filter is active.
  - **Summary invariance**: `displaySummary`, the four cards and the
    heading `N giao dịch · biến động …` always reflect the full
    register — only `groupEntries(filteredEntries)` narrows, so a
    visible filter can never bend the totals.
  - Transfer neutrality preserved — kind filter `Chuyển tiền` shows
    only transfer legs, which keep their neutral subtitles
    (`Nhận từ…/Chuyển đến… · không tính thu nhập/chi tiêu`); no row is
    ever reclassified.
  - Filtered-empty state (`Không có biến động nào khớp bộ lọc đang
    dùng` + `Xoá bộ lọc`) is distinct from the true empty-register
    EmptyState, which is untouched.
  - Client state only — no URL params, no persistence, intentionally
    unlike `/transactions` presets (register filters are ephemeral
    lookups, not saved workflows).
