## Boundaries

- Events contain only bounded elapsed time, pattern count, completion-mode enum, selected rank, save outcome and a short immediate-correction bucket.
- Amount, note, date, account/category IDs or names, merchant text, raw source evidence and persistent attempt identifiers are not emitted.
- A selected pattern is attributed only while its kind/account/category context remains unchanged; a manual override clears the rank.
- Failed saves emit a failure outcome but never a success event; no financial mutation behavior changes.
- No schema, migration, provider setting, production-data, layout or persistence change is included.

## Evidence limits

- The browser test observes the sanitized Vercel client event boundary; it does not prove deployed ingestion, retention or dashboard availability.
- The cohorts are observational and not randomized. Pattern-available versus no-pattern comparisons cannot establish causality.
- The first combined local run omitted required build/CAPTCHA environment and overlapped Next build processes. Fresh serial reruns with the same explicit test configuration as CI passed; the failed run is not acceptance evidence.
