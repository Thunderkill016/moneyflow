# PR #535 — defer secondary UI from initial load

**Issue:** #527
**Status:** draft implementation candidate; measurement and acceptance pending
**Lifecycle impact:** none yet. #527 remains current; this PR must not clear authority until same-methodology performance evidence and selected gates prove acceptance.

## Scope

- Conditionally mount the dynamically imported add-transaction dialog only after the user opens it.
- Conditionally mount the dynamically imported transfer dialog only after the user opens it.
- Remove eager priority/preload from the first below-fold landing story image so `next/image` can use its default lazy-loading behavior.

No financial semantics, authenticated data loading, mutation logic, schema, RLS, provider configuration or visual redesign is changed.

## Evidence and rationale

The current #527 packet identifies client JavaScript/main-thread work and unnecessary eager secondary UI/assets as the first bounded repository-controlled hypotheses. Current source confirms both dashboard dialogs were dynamically imported but still rendered while closed, and the first story image below the hero carried `priority`.

Official Next.js guidance documents conditional rendering of a dynamically imported modal so its JavaScript is requested only when first needed. Next Image guidance documents lazy loading as the default for images outside the viewport.
