## Boundaries

- Patterns require at least two exact occurrences and are ranked by frequency, canonical ledger recency and a deterministic structural tie-breaker.
- Transfers, split expenses, unreviewed or legacy-unknown rows and references absent from current account/category options cannot train a pattern.
- A pattern carries no amount, note or date and never saves automatically; the existing explicit transaction mutation and correction paths remain authoritative.
- The experiment is opt-in from `/capture/quick`; Dashboard and Transactions continue using the shared dialog without the selector.
- No schema, migration, provider, analytics, persistence, production-data or ownership boundary changes are included.

## Evidence limits

- Browser evidence uses repository-controlled demo fixtures and emulated viewports; it does not establish real-user time-to-ledger-truth improvement.
- Responsive and WebKit automation does not substitute for physical-phone review.
