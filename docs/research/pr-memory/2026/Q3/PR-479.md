- Why this next: `/reports` is the page whose entire job is understanding where money went, and grepping it found links only for switching period and reaching export — not one figure opened the transactions behind it. The dashboard received exactly this in PR #420, recorded there as the traceability half of the brand mechanism, and `PRINCIPLES.md` states that a figure and the rows behind it must agree or the drill-down is not shipped. A reader could see that 4.200.000 ₫ went to Ăn uống and had no way to check it.
- Deliberately not reusing `dashboard-drilldown.ts`: that module derives a whole calendar month, which is correct for a dashboard figure and wrong here. Reports carry week, month, year and custom windows, so the rows must be bounded by the report's own `currentStart..currentEnd` or they will not sum to what the reader clicked. A test pins a seven-day window surviving into the emitted `from`/`to`.
- The trap that shaped the design, found by reading `filterTransactions` rather than assuming: the account filter matches **both** `transaction.account` and `transaction.destinationAccount`. An account figure on a report is expense-only, so an account drill-down must carry `kind: "expense"`; without it a transfer *into* that account joins a list opened from an expense number and the total silently disagrees. `reportAccountDrilldownHref` exists as a named helper precisely so the kind cannot be forgotten at a call site, where its absence would look correct in review. The test proves the leak is real before proving the guard stops it, so it cannot pass vacuously.
- Two guarantees, deliberately different, and the difference is pinned by test: **accounts sum exactly**, because a split row belongs whole to the account that paid it — the asymmetry established in #476; **categories answer set membership**, because a split contributes only its own line to a category share while the ledger shows the whole transaction. The test asserts the account sum matches and, in the same fixture, that the category sum does **not**, so nobody can later claim the stronger guarantee for categories.
- Names that cannot be carried render as plain text rather than a link, because `/transactions` resolves both category and account by name and falls back to showing everything when a name does not resolve — a link built from an unresolvable name would open the whole ledger while appearing to open one slice.
- Changed: new `report-drilldown.ts` exporting `reportDrilldownFilters`, `reportDrilldownHref` and the two named helpers; the reports page renders category and account names as links when a name resolves; one new `.categoryLink` class in the existing reports CSS Module.
- Target size was designed for rather than discovered: `.categoryLink` takes its 44px minimum from `min-height` plus padding rather than a fixed box, so a long Vietnamese account name wraps instead of clipping, with `align-content` centring the text whether it wraps to one line or two. The cross-device audit caught exactly this class of regression in PR #420, which is why it was built in from the start.
