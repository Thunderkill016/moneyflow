- How this was selected, and what the audit corrected about my own measurement: a sweep for what a complete web product carries found the repository stronger than expected — a root `src/app/error.tsx` covers every route through nesting, 28 loading boundaries, 18 `EmptyState` callers, bulk actions, keyboard shortcuts, a PWA manifest with a share target, and a hand-built trend chart whose `aria-describedby` points at a screen-reader data table, which is better practice than importing a chart library. My first measurement reported "30 of 39 pages without an error boundary"; that was wrong, because Next nests boundaries and the root one covers them. It was corrected before being reported.
- The gap that was real: no `not-found.tsx` existed anywhere in the tree, so Next's built-in fallback rendered. Verified against production rather than inferred — `curl https://mfvn.vercel.app/khong-ton-tai-xyz` returned 404 with the built-in English title, in a system font, with no route back into the product.
- Changed: a Server Component with no client JavaScript, because a 404 is reached by definition on a path the app does not serve and must render from the HTML alone rather than waiting on hydration. It deliberately does not use `AppShell`, which needs a viewer, since this page renders for signed-out visitors too.
- The destination decision, which a test pins: it leads with `/` rather than `/dashboard`. The proxy sends an authenticated visitor to the dashboard and everyone else to the public page, so one link is correct for both without this file having to know which. A hard-coded `/dashboard` would strand a signed-out visitor at a login redirect, which is not a way back.
- Presentation is its own CSS Module rather than the `.route-error` globals. Those classes survive only through `docs/research/presentation-ownership-baseline.json`, and extending a baselined global to a new caller is exactly the failure that rejected PR #420. 44px targets come from `min-height` plus padding so a long Vietnamese label wraps instead of clipping, and the wrap gap is commented because the cross-device audit measures overlap once the row wraps.
- Guarded on purpose: five contract tests, because a 404 sits on no happy path. Deleting the file would silently restore the English fallback and nothing else in the suite would notice.
- One of those tests caught my own comment: the source quoted the English fallback sentence verbatim while the test asserted that sentence must not appear. The comment was reworded rather than the assertion loosened — the same class of mistake made earlier with a `:has()` mention and an `aria-busy` regex.
