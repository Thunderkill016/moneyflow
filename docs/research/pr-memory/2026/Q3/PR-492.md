- Affected capability or project boundary: risk-proportional gate selection, which `AGENTS.md` names as this script's sole authority.
- Status impact: candidate until merged. No capability changes; the evidence system that guards every other change gets one hole closed.
- Lifecycle impact: completes current slice. Issue #491 is registered and delivered in this same PR, which carries its own post-merge convergence: the board projection names PR #492, no successor slice is promoted, and projected current memory is updated here. `plan:resolve` intentionally reports NOT READY while this is unmerged.
- The gap, and it is measurable rather than argued: `playwright.audit.config.ts` runs the cross-device audit with `NEXT_PUBLIC_APP_MODE: "demo"`, so `src/lib/demo/transaction-fixtures.ts` defines every value that audit measures for overflow, target size and layout. `uiAuditMatchers` covered `src/app/**.{tsx,css}`, `src/components/**.{tsx,css}`, `public/`, `e2e/audit/` and `src/**.css` — nothing under `src/lib/`.
- Proven against the real regression rather than described: replaying the classifier's own matchers over the 17 files in PR #487's merge commit `c79a0e87` returns no UI-audit selection. That PR changed what every demo screen renders, merged green, and `main` went red on the next PR that did select the audit — `financial-value-overflowed` on `/reports`, a nine-digit income painting about 197px inside a 177px box, fixed in PR #490. The gate that measures exactly that never ran on the change that caused it.
- Browser smoke did run on #487, because `browserSmokeMatchers` carries `startsWith("src/")`, and it passed. That is not a contradiction: smoke checks behaviour and the audit measures layout. Recording it matters because a green smoke run was the reason the change looked safe.
- Changed: `startsWith("src/lib/demo/")` added to `uiAuditMatchers`, with a comment carrying the reason and the incident so the rule is not later read as arbitrary.
- Deliberately narrow, and the narrowness is tested: `src/lib/demo/` rather than `src/lib/`. Widening would select a ten-minute audit for most domain work, against the risk-proportional principle this repository states. A test asserts `finance.ts`, `planning/budgets.ts` and `inbox/parse-text.ts` still return `uiAudit: false`, so the rule cannot quietly widen. A third test replays PR #487's real file list and asserts it would now select the audit.
- Verified: `test:ci-policy` (**200 pass**, +3 new), `test` (1198 pass), `lint`, `check:knowledge`, `check:architecture`, and a direct call confirming `classifyChanges(["src/lib/demo/transaction-fixtures.ts"])` returns `uiAudit: true`. Because the script is in its own matcher lists, this PR selects every gate it governs, so the change is checked by the full set it controls.
- Limitation, not a pass: `test:db` was not run — `agent:doctor` reports `missing required capabilities: docker`. The proof that the new selection behaves correctly end to end is this PR's own CI run, not a local one.
- Remaining: a residual gap, stated rather than hidden. A change to a **computation** that alters displayed magnitudes — `calculateDashboardSummary`, a money formatter — still selects no UI audit. PR #487 touched `finance.ts` as well as the fixtures, so this narrow rule would have caught it, but a computation-only change of the same kind would still slip through. Closing that needs a signal other than a path match and is not attempted here.
