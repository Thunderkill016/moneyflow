## Evidence boundary

Supabase documents `amr` as authentication-method references with timestamps and documents sessions as refreshing access tokens over time. MoneyFlow therefore does not use access-token issuance time as evidence of a fresh login; a freshly issued JWT still fails deletion when the latest accepted interactive AMR timestamp is older than the 10-minute product policy.

Supabase `reauthenticate()` is documented for Secure Password Change and is not adopted as a generic destructive-operation proof. OpenID Connect `max_age=0` is used only to request fresh Google authentication; the Edge Function still decides deletion authority from verified claims after callback.

The OAuth expected-user cookie is a continuity guard, not authorization evidence. It is HttpOnly, scoped to `/auth/callback`, expires after 10 minutes and only prevents an accidental account switch from being treated as reauthentication of the previous account. The delete target remains exclusively the user ID from the newly verified bearer token.

OWASP guidance supports reauthentication before highly sensitive operations but does not prescribe MoneyFlow's exact 10-minute duration. That duration is an explicit project security judgment and is covered by tests.
