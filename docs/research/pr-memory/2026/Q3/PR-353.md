## The accepted limitation

R7 preserves archived row ids, which is what makes the round-trip proof
identity-exact rather than shape-equal. Ids are globally unique, so a restore is
refused with `restore_archive_id_conflict` while the source account's rows are
still live. The only production archive available came from the owner's primary
account, which still exists, so a hosted restore would have been refused before
writing anything. Proving it would have required purging a live account or
building and purging a third disposable one. The owner accepted the limitation on
2026-08-12 rather than manufacture a destructive probe.

Deterministic evidence stands in its place: pgTAP runs the complete
source → archive → restore into a fresh tenant → re-export → semantic comparison
chain against a real PostgreSQL on every CI run, exercising the same restore code
path production now runs.
