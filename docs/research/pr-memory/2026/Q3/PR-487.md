# PR #487 — fix(demo): make the first screen agree with itself

- Date: 2026-08-27
- Change class: Class 2 — demo-only presentation truth plus one domain computation. No schema, migration, RPC, RLS, provider or dependency change; authenticated ledger semantics are unchanged and no ledger mutation occurs.
- Affected capability or project boundary: demo mode — `src/lib/demo/transaction-fixtures.ts`, `calculateDashboardSummary` in `src/lib/finance.ts`, and the four demo consumers in `transaction-store.ts`, `server/finance.ts`, `server/reports.ts` and `server/budgets.ts`.
- Status impact: candidate until merged. On merge, demo mode stops presenting a figure that cannot be checked. Authenticated capability is untouched.
- Lifecycle impact: completes current slice. Issue #486 is registered and delivered in this same PR, which carries its own post-merge convergence: the board projection names PR #487, no successor slice is promoted, and projected current memory is updated here. `plan:resolve` intentionally reports NOT READY while this is unmerged.
- How it was found, and this is the part worth keeping: the owner asked what I thought of the interface. I had spent the whole session reading code, CSS and test assertions without rendering a single pixel, so I said so and went and looked — downloading 304 rendered PNGs from the cross-device audit artefact of run `33000916241`. The defect is visible in the desktop dashboard screenshot and was invisible in every file I had read.
- What the screenshot shows: three panels on one screen disagreeing. The month statement reads "Tiền ra 4.209.000 ₫", the category panel reads "Chưa có chi tiêu tháng này", and the weekly summary reads "Tuần này chưa có thu–chi được ghi", while the recent-transactions list directly below shows a row labelled "Hôm nay".
- Cause one: `calculateDashboardSummary` added `MONTHLY_EXPENSE_BEFORE_SAMPLE`, 4.209.000 ₫ that no transaction produces, when `isDemo`. The category panel builds from real rows, so the two could never agree, and a reader who clicked through to check the figure found nothing behind it. Demo and authenticated now compute expense identically; the only remaining difference is where the balance comes from.
- Cause two: the fixture pinned `occurredOn: "2026-07-14"` beside a hard-coded `relativeDate: "Hôm nay"`. Written on 2026-07-14 and read on 2026-08-27, that row claimed to be today for six weeks while sitting in a month every month-scoped panel correctly reported as empty. Dates and their labels now derive from one resolved date, which is what prevents them drifting apart again — the label cannot disagree with the date because it is computed from it. The salary note derives its month for the same reason: a fixed "Lương tháng 7" is the same untruth as a fixed "Hôm nay", only slower to notice.
- Changed: `sampleTransactions` becomes `sampleTransactionsFor(today)` over a `DEMO_SEEDS` list carrying `daysAgo` and a UTC clock portion rather than stored dates; all four consumers pass their own resolved date, so a warm server module cannot freeze the demo's idea of today, and the browser store resolves it per call so a tab left open overnight does not keep yesterday's "Hôm nay"; `MONTHLY_EXPENSE_BEFORE_SAMPLE` is deleted.
- A test was pinning the invention. `"demo dashboard summary preserves visible factual totals only"` expected `expense: 4_309_000` — one real 100.000 ₫ expense plus the constant — so 97.7% of a figure asserted by a test named for factual totals was invented. Its expectation now matches the rows that exist, and a new sibling asserts demo and authenticated compute the month identically.
- Verified: `typecheck`, `lint` (0 errors), `test` (**1191 pass**, +7 new), `check:architecture`, `check:css-ownership`, `check:code-css-ownership` (after a real build, as that gate requires), `check:knowledge`, `test:ci-policy`, `check:migrations`, and `npm run build` with `NEXT_PUBLIC_APP_MODE=authenticated`. The new tests run across five dates including a leap day and both a month and a year boundary, and one of them pins the visible symptom directly: the statement and the category panel must agree on whether the month is empty.
- Limitation, not a pass: `test:db` was not run — `agent:doctor` reports `missing required capabilities: docker`. `test:e2e` and `test:ui-audit:pr` were not run locally, and that matters more than usual here because this changes what every demo screen renders; the browser gates on the exact head are the authoritative evidence, and no screenshot of the corrected dashboard has been taken.
- Remaining: `calculateDashboardSummary` still defaults `today` to the literal `"2026-07-14"` when a caller omits it. That is the same class of defect and is deliberately **not** fixed here — the single production caller passes `today`, and changing the default would make the tests that omit it depend on the real date, which is a different scope. Recorded rather than silently left.
- Production/provider evidence: not applicable. No provider write, deployment or production-data access. The screenshots were read from a CI artefact, not from production.
