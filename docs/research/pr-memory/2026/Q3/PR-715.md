# PR #715 — Named saved filter presets on /transactions (device-local)

- Date: 2026-09-25
- Change class: Class 2 (user-interface change — CI selects verify +
  browser smoke + cross-device UI audit, codeql; database false per
  doctor). No schema, no migration, no server action.
- Affected capability or project boundary: `/transactions` workspace
  toolbar (`src/components/transactions/transactions-workspace.tsx` +
  CSS module) and a new browser-local store
  `src/lib/saved-transaction-filters.ts` — same persistence class as
  `ledger-duplicate-dismissals` (localStorage, validated reads, never
  ledger data, never synced).
- Status impact: the saved-filters gap from the transactions-page
  product comparison is closed. Tags/labels, per-row cleared state,
  attachments and calendar view remain open and are not touched.
- Changed:
  - Store: name is identity (saving an existing name upserts), cap of
    8 presets, 40-char names; reads validate — fully-corrupt JSON is
    wiped, malformed entries are dropped individually while valid ones
    survive; `sameSavedFilterValues` structural equality (query
    compared trimmed) marks the preset currently in effect.
  - Viewer scoping (director round 2, P1): the storage key is
    `…-v1:<viewerId>` — presets carry readable names, free-text
    queries and account/category names, so an unscoped key would leak
    them to the next sign-in on the same browser. The page passes
    `viewerId={viewer.id}` (Supabase sub; `demo-user` in demo) as a new
    required prop; legacy unscoped data is deliberately not adopted.
  - Write-failure handling (director round 2, P2): `setItem` is
    wrapped — quota/private-mode denial returns
    `{ ok: false, reason: "storage" }` instead of throwing
    `QuotaExceededError` into the click handler; `storage === null`
    also fails explicitly rather than reporting `ok: true`. The UI
    keeps the name form open and shows a retryable warning notice.
  - Storage-access guard (director round 3, P2): `defaultStorage()`
    catches a denied `window.localStorage` getter (SecurityError) and
    degrades to `null`, so read/save/delete take the explicit
    no-storage path instead of throwing during parameter
    initialization.
  - UI: preset chip row renders only when presets exist; the active
    preset is highlighted with `aria-pressed`; each pill pairs the
    recall tap (left) with a × delete (right) so a destructive tap
    never shares the recall target; "Lưu bộ lọc này" + inline name
    form sits at the foot of the "Bộ lọc khác" disclosure and is
    disabled when no filter is active.
  - Apply writes all nine filter fields (query, kind, account,
    category, review, from/to date, min/max amount); the existing
    `transactionFilterSearch` URL-sync effect then serialises the
    result, so a loaded preset is deep-linkable for free.
  - Feedback uses the existing `showNotice` slot; presets hydrate
    after mount via `requestAnimationFrame` (same pattern as dupe
    dismissals) so SSR never disagrees with the client.
