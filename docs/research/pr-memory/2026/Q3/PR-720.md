# PR #720 — Server-persisted advisory dismissals (cross-device "Bỏ qua")

- Date: 2026-09-25
- Change class: Class 3 — new user-owned table + RLS + security-definer
  RPC + server action. Owner granted autonomous merge authority this
  session ("toàn quyền làm việc merge … ko cần hỏi ý kiến").
- Affected capability or project boundary: dismissal state for the
  ledger-duplicate strip (`ledger_dupe` scope) and recurring-suggestion
  cards (`recurring` scope). Ledger truth untouched — deleting rows only
  re-surfaces a suggestion.
- Superseded issue, roadmap or claim: owner-reported defect — "đã nhấn
  bỏ qua trên điện thoại rồi mà" — the banner reappeared on PC because
  dismissals were browser-local `localStorage`.
- Design basis: pattern keys are deterministic fnv1a hashes of the
  bucket (`account|kind|amount|desc` for ledger dupes, `expense|note`
  for recurring), so identical ledger data produces identical keys on
  every device — persisting the key is sufficient to share the decision.
- Changed:
  - `pattern_dismissals` table: composite PK `(user_id, scope,
    pattern_key)`, `pattern_key ~ ^[0-9a-f]{8}$`, scope CHECK whitelist
    (`ledger_dupe`, `recurring`), RLS select-own policy, `SELECT`-only
    grant to authenticated — direct writes refused.
  - `dismiss_pattern_keys(text, text[])` security-definer RPC,
    `search_path = ''`, derives `user_id` from `auth.uid()` (never
    client-supplied), validates scope/keys/batch≤500 before any insert,
    `ON CONFLICT DO NOTHING` idempotency (second device re-dismissal is
    a no-op, not an error).
  - Lifetime anchored on `public.profiles(id) ON DELETE CASCADE`:
    tenant purge deletes the profile and the cascade removes dismissal
    rows; auth-user delete cascades the same way. Deliberately absent
    from `ARCHIVE_TABLE_INVENTORY`/export/restore — UI preference is not
    ledger truth; an orphaned dismissal only re-surfaces a suggestion.
  - `getPatternDismissedKeys(scope)` server loader: `null` for demo
    (component keeps the localStorage path), `[]` on read error —
    honest degradation (suppressed suggestion reappears) rather than
    silently pretending the read succeeded.
  - `dismissPatternKeysAction` server action: zod-validated scope +
    keys, non-demo viewer required, RPC write.
  - Components (`transactions-workspace`, `commitments-page`):
    `null`-sentinel init from server props prevents dismissed-group
    flash; demo unchanged (localStorage read after mount); dismiss is
    optimistic-hide + revert + error notice on failure — the UI never
    claims a dismissal the account did not store. Success notice text
    preserved ("Đã bỏ qua gợi ý trùng.").
  - pgTAP: new `pattern_dismissals.test.sql` (12 assertions — grant
    refusal, idempotent RPC, validation rejects, tenant isolation,
    auth-user cascade, anon EXECUTE denial + claim-less guard);
    `schema_and_rls` plan 82→85; `security_definer_contract`
    inventory 42→43 with the reviewed-boundary comment.
  - `supabase/migration-identity.json` baseline extended deliberately
    via `check-migration-identity.mjs --write`.
- Round-2 (director review, three findings — all fixed):
  - pgTAP anon assertion expected P0001 but anon lacks EXECUTE →
    PostgreSQL raises 42501 before the body runs; split into an anon
    grant-denial assertion plus a claim-less `authenticated` call that
    exercises the in-body `authentication_required` guard.
  - `security_definer_contract` count moved 42→43 with a comment line
    naming the new reviewed boundary.
  - Rejected server actions (offline/transport) previously bypassed the
    optimistic rollback because only resolved `{ok:false}` was handled;
    all three call sites now route rejection through the same revert +
    error-notice path (`markSuggestionHandled` keeps the saved
    commitment but reverts the local hide so local state never claims a
    dismissal the account did not store). Pinned by source-contract
    tests in `pattern-dismissals.test.ts`.
- Verified locally: typecheck, lint (0 errors), 1888/1888 unit tests,
  check:migrations, check:rls, check:architecture, check:knowledge,
  ci-policy 191/191, build 52/52 routes, browser smoke /transactions +
  /commitments @390/1280 — 0 console errors, no h-scroll. pgTAP runs
  in CI (no local Docker).
- Open follow-ups: none for this slice. LocalStorage keys from earlier
  versions are not migrated to the server (a one-time re-dismiss is the
  documented cost — keys are pattern-level so re-dismissing once
  silences the pattern everywhere).
