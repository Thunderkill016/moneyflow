# PR-721 — feat(reports): income categories, period navigation, savings rate

- Status: open

- Head: `ef17938f`

## Why

Surface audit of `/reports` against Money Lover / MISA / YNAB / Monarch found
three real gaps: income had categories in the ledger but no breakdown in the
report, moving a period required hand-typing a custom range, and "Còn lại"
carried no kept-share context.

## What

- `FinancialReport.incomeCategories`: income grouped by category, same
  split-distribution + six-month strip rules as `categories`, shares over
  period income. `savingsRatePercent`: `net/income`, `null` at zero income,
  negative when overspent.
- `adjacentReportRanges(range, today)`: presets step by calendar unit, custom
  windows by their own span (equal-length, same rule the comparison totals
  use). `next` is `null` when entirely future; clamps at `today` on overlap.
- `reportIncomeCategoryDrilldownHref`: `kind=income`, refuses blanks.
- UI: chevrons reuse `.periodLink` (44px targets) inside `.periodNav`;
  navigation always emits `period=custom&from&to` because a past calendar
  window is not a preset. `ReportsWorkspace.todayIso` stamps the server's
  clock so clamping agrees with range resolution.
