# PR #710 — Goal ↔ transaction linkage: annotation-only tag

- Date: 2026-09-24
- Change class: Class 2 (schema + runtime + UI)
- Affected capability or project boundary: `financial_transactions`, `create_money_transaction`, `update_money_transaction`, `transaction_feed`, `deleted_transaction_feed`, `get_dashboard_bundle`, `guard_reconciled_transaction_mutation`, archive export/validate/restore generation chain, add/edit transaction dialogs, transaction rows, goals list page, demo optimistic path.
- Status impact: transactions gain an optional `goal_id` annotation — "which goal is this related to". It is explicitly **not** funding provenance: `savings_goal_allocations` remains the single authority for goal progress.
- Changed:

  - Client: `Transaction.goalId/goalName`, `GoalOption`, sentinel-aware inputs; edit dialog hides picker on transfers and preserves the tag when goal data is unavailable (no silent clear); archived tagged goal stays selectable as history; add dialog offers active goals only and retains the tag through the unsent-capture draft; rows render a quiet "Mục tiêu ·" line; goal cards render "N giao dịch liên quan" via a separate count query; demo mode uses opaque `GoalOption` ids (no uuid validation).
  - `goal-linkage-archive-validator/ingress` mirror the payee generation layer; both ingress points wired.
