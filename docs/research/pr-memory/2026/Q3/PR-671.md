# PR #671 — Roll prior months' under/overspend into effective budget available

- Date: 2026-09-22
- Change class: Class 2 (bounded UI/flow — one planning surface; domain math stays in `src/lib`)
- Affected capability or project boundary: `src/lib/planning/budgets.ts` (rollover domain functions), `src/server/budgets.ts` (`BudgetsWorkspace.priorBudgets` + bounded `budget_progress` window read), `src/components/planning/budgets-page.tsx` (effective figures + explanation copy).
- Status impact: budgets were month-isolated; the budgets page now carries each prior budgeted month's `limit − spent` into the viewed month's effective available (`limit + carry − spent`), matching the YNAB/Actual Budget carry-forward expectation noted in the competitive gap records.
- Changed: `budgetRollover` sums signed per-month deltas per category over a capped 12-month lookback (`BUDGET_ROLLOVER_LOOKBACK_MONTHS`), applied in both the Supabase range read and the domain sum; months with no budget row contribute nothing rather than an invented deficit; carry never clamps. Effective threshold/status reuse the calm bands, with an explicit `available < 0 → "over"` guard for carried-overspend edges. The card prints the honest line (`Chuyển từ tháng trước: +X` / `Trừ vì vượt hạn mức tháng trước: −X`, naming the month count when deeper), the summary total and header truth note state the rule. Demo path runs the same module over its one seeded month of history.
- Verified: budgets.test.ts 37/37, full suite 1505/1505, typecheck, lint (1 pre-existing warning), build 51 routes, check:knowledge, ci-policy 191/191, check:architecture, check:css-ownership.
- Remaining: dashboard featured-budget card and `budgets.status` capability stay month-scoped — the card reads the bundle RPC (needs a migration to extend) and the capability's documented `remaining = limit − spent` formula is unchanged; demo carry is limited to the one seeded prior month; lookback cap of 12 months is a product bound, not a user setting.
- Production/provider evidence: none (render-time arithmetic over existing `budget_progress` rows; no migration; browser smoke delegated to CI lanes).
- Superseded issue, roadmap or claim: the budgets-page truth note previously claimed MoneyFlow never accumulates limits across months — updated to describe the rollover contract.
- Lifecycle impact: if users need deeper history, raise `BUDGET_ROLLOVER_LOOKBACK_MONTHS` or switch to a created-at-based window — the domain bound is a single constant; extending rollover to the dashboard requires a bundle-RPC change and is a separate decision.
