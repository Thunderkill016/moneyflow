## Why one authority mattered more than more fields

#354's doctor consumed the classifier for gate flags but carried its own hard-coded
gate commands and provider check list. Two copies of a rule are worse than one copy
plus prose: the copies disagree silently and nothing says which is right. So the
projection imports the classifier for path → gate selection and owns only what the
classifier deliberately does not carry.

The load-bearing guard is behavioural rather than textual: for eight diff shapes the
policy's `classification` must be byte-identical to `classifyChanges`' own output, so
a second implementation cannot hide behind a passing suite.

## What the evaluation caught, recorded because it is the useful part

Three of the seven were guards that looked like guards but could not fail:

- all three single-source guards were defeatable — a third policy module, a second
  gate table in the doctor and a concatenated module specifier passed all 35 tests
  while two live gate tables disagreed;
- `granted: false` was frozen on the catalogue but not on the emitted object a
  consumer reads, and the test proving it asserted a `"use strict"` throw inside an
  ES module, where the directive is decorative;
- `deriveRiskClass` defaulted an absent file list to `[]`, skipping Class 3
  detection and answering "Class 1", with a test locking that in as intended.

Under-reported boundaries were the other sharp edge: `supabase/functions/_shared/**`
holds the recent-auth guard that decides whether a caller may destroy an Auth
identity and implied no boundary at all, while `delete-account/index.ts` implied one.
