## Evidence boundary

Forge's live MCP implementation supports a useful delivery principle beyond its product document: context should be retrieved at the moment it changes an action. `forge_project` is described as a pre-task call and `forge_inflight` as a pre-PR call; the server does not run a model or make decisions. The GitHub API adapter explicitly omits local-only facts it cannot observe instead of inventing them. MoneyFlow already follows the same trust boundary through repository-backed memory, provider reads and fail-closed verification, so PR #317 does not add another memory service.

The Forge research log itself provides a counterexample: it records some findings as applied to files that are absent on the current default branch. MoneyFlow therefore treats "research says it was adopted" as a claim that still needs a live artifact/evidence target. This reinforces the selected traceability direction but is not converted into another parser rule in this PR.

No Forge code is copied. The selected invariant is reimplemented within MoneyFlow's existing work-packet checker using Node standard-library parsing and existing CI-policy ownership.
