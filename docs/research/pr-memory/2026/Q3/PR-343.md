## What this slice does and does not establish

Establishes an executable, fail-closed archive contract: versioned envelope, a
canonical nineteen-table inventory anchored to `purge_user_tenant_data`,
source-neutral row shapes carrying no ownership, and validation that rejects
before any mutation path exists.

Does **not** establish Recover capability. There is no exporter and no restore
function, so no user can archive or recover anything yet.

## Evidence boundaries recorded rather than overclaimed

- The validator receives already-parsed values. RFC 8259 §4 notes duplicate
  object member names are not interoperable, and `JSON.parse` keeps the last
  before the validator runs, so no raw-duplicate-key protection is claimed.
- Duplicate-restore detection requires persistent restore metadata and is
  deferred to the database slice.
- `accounts` has no `is_default` column, so the bootstrap-account allowance in
  the empty-target policy is count-based rather than structurally identified.
- `account_reconciliation_events.difference_minor` is omitted from the archive
  because the schema permits ±18014398509481982 — twice the JavaScript
  safe-integer bound — and it is exactly
  `statement_balance_minor - calculated_balance_minor`.
- No pgTAP ran. A green `database` job in this PR means "Database checks not
  required", which is not pgTAP execution.
