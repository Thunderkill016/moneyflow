## Why the harness came first

`playwright.config.ts` and `playwright.audit.config.ts` both pin
`NEXT_PUBLIC_APP_MODE: demo` in `webServer.env`, overriding the `authenticated`
value `ci.yml` sets at job level. No browser test had ever run authenticated. In
demo mode reading browser storage is the correct behaviour, so MF-01 and MF-02
were invisible to a fully green suite — including
`e2e/authenticated-deterministic-rules.spec.ts`, which despite its name seeds
`localStorage` and runs in demo.

A local Supabase stack needs Docker and CI is configured with a placeholder
project, so neither can boot an authenticated browser. The harness therefore
runs the real app against a deterministic double on loopback.

## Scope limit, stated plainly

The double proves application-layer ownership: which source each surface reads
from, through the real `@supabase/ssr` client, route loaders and server
components. It proves nothing about PostgreSQL — not RLS, not tenant isolation,
not SQL invariants, not RPC bodies. Those remain `npm run test:db` and must not
be inferred from a green authenticated run.

The double is strict: any unimplemented path, table, RPC or PostgREST filter
returns 501 and is recorded, and every test asserts the miss list is empty. Its
`/auth/v1/user` rejects a token it did not issue, so a session-less browser
cannot be promoted to an authenticated one.
