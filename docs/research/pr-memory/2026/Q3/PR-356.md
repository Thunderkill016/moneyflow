## Why the loop was re-derived from code

The archived P0–P11 UI checklists no longer describe current runtime behavior, so the
scenario set comes from reading the shipped components. That is what turned up the
three checks worth the most: a retried save after a network failure (the dialog
carries an idempotency key created before the attempt and cleared only on success),
integer đồng **on entry** (`parseMoneyInput` strips every non-digit while the field
advertises a decimal keypad, so `12,5` yields 125 đồng), and the recorded row's date.

## What the evaluation caught, recorded because it is the useful part

Four citations in my own reconnaissance were false — a CSS file that does not exist,
a dead `ui/money-value.tsx` with zero importers, `Nhập nhanh` where the mobile tab
renders `Ghi`, and `Số dư hiện tại` presented as visible text when it is an
aria-label. Two scenarios asked for the wrong thing: PP-10 demanded that a
current-month dashboard agree with an unfiltered register, which would have produced
a **fail on correct behavior**, and PP-02's invariant contradicted vi-VN thousands
separators.

The validator had two structural holes worth remembering: a missing `## Declaration`
section validated clean because `indexOf` returned -1, removing the only
physical-versus-emulated attestation; and `seven-day-*.md` files were skipped
entirely while the packet claimed they were scanned.
