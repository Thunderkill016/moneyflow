# PR #695 — Finish noticeTone sweep + '/' global search shortcut

- Date: 2026-09-23
- Change class: Class 1 (bounded mechanical UI plumbing; no migration, schema, RPC or provider change)
- Affected capability or project boundary: `src/lib/toast-presentation.ts` consumers via `AppShell` `notice`/`noticeTone`; `src/lib/app-shortcuts.ts` + `src/components/layout/app-shell.tsx` keydown path; `src/lib/push-client.ts` tone mapping.
- Status impact: the explicit-tone convention from #683 now covers every live AppShell notice surface; the substring heuristic in `resolveToastPresentation` is fallback-only. `/` joins ⌘K as a global ledger-search trigger on pages that do not own it.
- Changed: `noticeTone` state threaded through `accounts-workspace`, `account-reconciliation-page`, `categories-page`, `connected-apps-page`, `delete-account-page`, `appearance-/export-/notification-/privacy-settings-page`, `planning/{budgets,commitments,goals,income-templates}-page` and `inbox/{capture-paste,capture-share,direct-csv-import,import-preview,imports,rules}-page` — each pairs message + tone in one `showNotice`/`notify` helper and clears both on timeout (the #683 convention). `push-client.ts` gained `notifyResultTone` next to `notifyResultMessage` (`shown` → success, `denied`/`unsupported` → warning, `error` → error, skipped → info). `app-shortcuts.ts` added `isSlashSearchShortcut` (bare `/`, modifiers rejected) and `pathnameOwnsSlashSearch` (`/transactions` only). In `app-shell.tsx` the `/` path uses `isEditableKeyboardTarget` — stricter than the ⌘K `shouldIgnoreShortcutTarget` carve-out on purpose, since a typed `/` inside any field (including `data-app-search` inputs) must remain text — and returns without `preventDefault` on `/transactions` so the ledger workspace's own `/` (toolbar field, #687) keeps sole ownership regardless of listener ordering. No user-facing copy changed; every quoted literal removed in the diff reappears verbatim.
- Verified: `npm run typecheck` clean, `npm run lint` 0 errors (1 pre-existing warning in `quick-add-defaults.test.ts`, untouched), `npm run test` 1754/1754 (3 new app-shortcuts tests), `check:knowledge`, `test:ci-policy` 191/191. Browser smoke and visual audit delegated to CI lanes.
- Remaining: `capture-upload-page.tsx` still wires `AppShell` `notice` but no code path ever sets a message — dead plumbing left as-is (a cleanup could delete the state or add the missing notice). `reports-page` `rangeNotice` and the various inline `Alert`/`setError`/`actionError` surfaces are a different plumbing layer that cannot carry a toast tone — intentionally outside this sweep. `/` is a dead key on `/transactions/trash` (no searchBar, pathname under `/transactions/`), matching existing ⌘K behavior. A toast carrying `noticeAction` still forces the declared-tone-or-`info` + restore-icon presentation from `toast-presentation.ts`, so goals' warning-styled action toast keeps the restore icon.
- Production/provider evidence: none (client-only presentation/interaction layer; production verification remains an owner decision post-merge).
- Superseded issue, roadmap or claim: none.
- Lifecycle impact: any future `AppShell` notice caller should set `noticeTone` at creation time rather than leaning on the Vietnamese-substring heuristic; if another workspace wants a local `/`, add its pathname to `pathnameOwnsSlashSearch` rather than racing the global handler.
