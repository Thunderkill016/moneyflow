## Provider preflight/risk review

Current affected production tables are small at the inspection point (47 transactions, 47 transaction entries, 6 Inbox candidates, 3 accounts, 33 categories, 0 budgets, 0 provenance), reducing expected lock duration without removing production risk.

Per-source review found:

- FK/read-plan index migrations use ordinary `CREATE INDEX`; PostgreSQL permits reads but blocks writes during ordinary index build.
- transaction review adds a constant-default `NOT NULL` enum column plus index/view/RPCs; PostgreSQL 17 avoids a table rewrite for a non-volatile constant default, but `ALTER TABLE` still requires a strong schema lock.
- reconciliation has the largest lock/constraint surface: new domain tables plus constant-default state and constraints/indexes on `transaction_entries`.
- rules adds a new RLS table plus nullable candidate evidence columns/triggers/RPCs; existing candidate rows satisfy the nullable-pair shape.
- audit adds an append-only audit table and triggers that immediately become part of every future financial mutation; no historical audit backfill occurs.
- audit also installs the complete current tenant purge, including provenance/rules/reconciliation/audit cleanup.
- request-id constraint should follow audit immediately so any new audit rows are constrained under the final contract.

The exact filename order is also the semantic dependency order and must not be rearranged.
