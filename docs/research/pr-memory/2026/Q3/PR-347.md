## Why this layer exists

`JSON.parse` resolves duplicate object member names silently by keeping the last,
so `{"archive_version": 9, "archive_version": 1}` reaches a validator looking
valid. R5 recorded that it could not make the claim. R8 reads the raw text first.

The scanner is deliberately not a JSON parser — it builds no values and decides no
types, only tracking object scopes well enough to identify member names, with
`JSON.parse` remaining the syntax authority. Names are compared **decoded**, so an
escaped spelling collides with its plain form.

## Decisions recorded

- **No dependency.** A bounded scanner over a well-specified grammar beats added
  supply-chain surface for a task that needs only name-and-scope tracking.
- **Fatal UTF-8**, because the default decoder rewrites malformed bytes to U+FFFD
  and turns a corrupt file into a parseable one. Leading BOM tolerated; no
  encoding sniffing.
- **64 MiB** from measured shapes (~786 B per transaction with entries ≈ 85,000
  transactions). **Depth 24** deliberately equals R5's forbidden-key scan bound,
  so nothing accepted can nest deeper than the validator inspects.
- Rejections carry byte offset and depth only — never a member name, since
  `column_map` keys are user-derived statement headers.
