# PR #672 — Diacritic-insensitive ledger and activity search

- Date: 2026-09-22
- Change class: Class 1 (bounded code in one subsystem — text search filtering)
- Affected capability or project boundary: `src/lib/search-text.ts` (new shared `normalizeSearchText` fold), `src/lib/transaction-filters.ts` (`filterTransactions` query match), `src/server/capabilities/transactions-search.ts` (`transactions.search` text filter), `src/lib/activity.ts` (Activity `searchText` + query normalization).
- Status impact: candidate — Vietnamese queries typed without Telex diacritics (`an uong`, `tien dien`) now match accented ledger/activity text; no issue/roadmap item superseded.
- Changed: one fold applied to haystack and needle — `đ`/`Đ`→`d`/`D` (no Unicode decomposition exists for them), NFD, strip combining marks (`\p{M}`), `toLocaleLowerCase("vi")`, trim. Mirrors `normalizeDesc` in `src/lib/inbox/detect.ts` minus its fingerprint punctuation collapse; `detect.ts` keeps its own copy so fingerprint equality is untouched. Empty query still matches everything; substring and case-insensitive semantics preserved (`an` still lands inside `bàn`; queries typed with diacritics still match). Edge note: a whitespace-only `transactions.search` `text` now folds to empty and matches all rows instead of only rows literally containing that whitespace.
- Verified: typecheck, lint (1 pre-existing warning), full suite 1503/1503 (1492 + 11 new), check:knowledge, ci-policy 191/191, check:architecture, check:capabilities, build 51 routes (local `node_modules` symlink swapped for a `cp -al` copy for Turbopack, then restored; CI-equivalent env).
- Remaining: `src/lib/inbox/apply-rules.ts` rule `contains` matching is still lowercase-only — deliberately out of this slice; candidate fields beyond Activity's `searchText` (e.g. inbox list filtering elsewhere) were not audited for the same gap.
- Production/provider evidence: none (pure client/domain substring change; browser smoke delegated to CI lanes).
- Superseded issue, roadmap or claim: none.
- Lifecycle impact: if folded substring matching produces noisy hits on short queries (e.g. `uong` inside `luong`), consider token-boundary matching as a separate, larger decision.
