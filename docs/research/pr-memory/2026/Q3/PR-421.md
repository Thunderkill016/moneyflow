# PR #421 — chore: type-check the e2e specs

- Date: 2026-08-18
- Change class: Class 1 — bounded tooling change in one place: `tsconfig.json` stops excluding `e2e`, and the four resulting type errors are fixed. No runtime, product, schema, RLS, Auth, provider or CI-workflow change.
- Affected capability or project boundary: static verification coverage. Every Playwright spec is now type-checked, including the performance measurement harnesses this project relies on for its evidence.
- Status impact: candidate. Phase 4.3 of `docs/plans/PRODUCT_DEVELOPMENT_PLAN.md`. Touches no release gate and no issue; #403, #417, #418 and RRB-08 are unaffected.
- Changed: removed `"e2e"` from the `exclude` list in `tsconfig.json`; supplied the missing second generic to two `page.evaluate` calls, in `e2e/audit/minimum-target-size.responsive.audit.spec.ts` and `e2e/audit/safety-review-states.audit.spec.ts`.
- Why it existed: with a single type argument, `page.evaluate<R>` leaves the *argument* type as `void`, so a destructured parameter was typed `void` while the real value was passed at the call site. Nothing reported it because no spec in `e2e` was ever statically checked. That exclusion is also how a wiring mistake in the #403 measurement harness reached a full local run before anything caught it — the run caught it, the type checker could not.
- These were typing gaps, not runtime bugs, and that was verified rather than assumed: the arguments are genuinely passed (`}, MINIMUM_TARGET_SIZE)` and `requireAlert: options.requireAlert === true`); the target-size audit demonstrably works, since it caught a real 44px regression in #420 on the same day; and the failure mode rules itself out, because had `minimumSize` been `undefined`, `rect.width + 0.01 >= undefined` would evaluate false for every control, so every control would have been reported undersized and the audit would have failed loudly instead of passing. Nothing was silently vacuous.
- Verified: `npm run typecheck` is clean **with `e2e` included**, which is the whole point of the change. Both touched specs still behave identically — 29 audit checks pass at `chromium-phone-320` across `minimum-target-size` and `safety-review-states`. `lint`, `check:architecture`, `check:knowledge`, `test:ci-policy` and 1073 unit tests pass. Exact-head provider checks are authoritative.
- Remaining: nothing for this change. Phases 4.1 (#417 draft-to-ready CI false-green race) and 4.2 (#418 Dependabot alerts held open by our own `postcss` override) stay open and both need an owner decision before an agent touches them, since one changes CI and required-check behaviour and the other changes a deliberate pin whose reason is unrecorded.
- Production/provider evidence: not applicable. No provider write, deployment, production-data access or production verification.
- Snapshot update: not applicable while Status impact remains candidate. On merge this does change durable verification truth — static coverage now includes the e2e suite — so the capability inventory should say so at closeout rather than leaving the impression that `typecheck` covers everything it appears to.
- Superseded issue, roadmap or claim: retires the limitation recorded in `PR-415.md` and `PR-419.md` that `tsconfig.json` excludes `e2e` so no Playwright spec is statically checked. That statement was true when written and is no longer true after this merge.
