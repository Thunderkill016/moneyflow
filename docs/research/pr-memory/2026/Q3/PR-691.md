# PR #691 — Goal allocation history surface + deadline pace status

- Date: 2026-09-23
- Change class: Class 2 (bounded UI/read change on `/goals` plus one count prop into the dashboard client boundary; no migration, schema, RPC or provider change — the new select rides the existing `savings_goal_allocations_select_own` RLS policy and grant)
- Affected capability or project boundary: `src/lib/planning/goals.ts` domain module, `src/server/goals.ts` workspace loader, `src/components/planning/goals-page.tsx` card, `src/lib/attention.ts` chip, dashboard page wiring, `src/lib/vietnam-date.ts`, `goals.status` capability fixture (output unchanged)
- Status impact: `savings_goal_allocations` was write-only since `20260714000600_savings_goals.sql` (the adjust RPC inserts at :97-98; the select policy existed at :32-35). Goals now show a 30-day funding-history line and a deadline-pace line; Home can carry a count-only "quá hạn hoặc chậm nhịp" chip.
- Changed: `GoalAllocation` type + `goalFundingInWindow` (positive amounts only — releases are not "đánh dấu"), `goalPaceStartDate` (`created_at` anchor, earliest allocation as fallback), `expectedAllocatedByNow` (linear `target × elapsed/total`, clamped [0, target], divide-before-multiply for safe-integer headroom, null on zero-length plans), `goalPaceStatus` (`ahead`/`on-track`/`behind`/`past-deadline`; withholds when archived, deadline-less, achieved or anchor-less), `countGoalPaceAttention` (overdue ∪ behind, count only so goal objects stay out of the dashboard client boundary). `GoalsWorkspace.allocations: GoalAllocation[] | null` — null in demo and on read failure so the card withholds rather than seeds fiction (same convention as `reserve: null`). `mapGoalRow` gains `createdAt` normalized to the Vietnam calendar day via new `dateInVietnam` (UTC slicing would disagree with `todayInVietnam` around midnight); `created_at` is `nullish` in the schema so deploy skew against an older `get_dashboard_bundle` projection stays parseable.
- Design decisions: pace copy names the linear assumption ("Nhịp đều đến hạn…") because the user declared a deadline, not a schedule; judgment words ride in text, not color; `past-deadline` renders no pace line (the existing overdue context already tells it); demo-created goals get `createdAt: today` (a true birth anchor) while seeded demo goals keep `null`. No completion-date extrapolation anywhere.
- Verified: `npm run typecheck` clean, `npm run lint` 0 errors (1 pre-existing warning in `quick-add-defaults.test.ts`, untouched), `npm run test` 1720/1720 (12 new domain tests covering window totals/counts, expectation clamps, withhold conditions and states, plus 2 attention-chip tests), `npm run build` green, `check:knowledge`, `test:ci-policy` 191/191, `check:css-ownership`, `check:architecture`. Browser smoke and visual audit delegated to CI lanes.
- Remaining: behind-pace counting on the dashboard is inert on the primary `get_dashboard_bundle` path because the bundle projection does not emit `goal.created_at`; the additive follow-up is a one-line bundle field plus a pgTAP pin. `/goals` reads through `getGoalsWorkspace`, which now selects `created_at`, so the card-level feature is unaffected.
- Production/provider evidence: none (read-only UI/domain change; production verification remains an owner decision post-merge).
