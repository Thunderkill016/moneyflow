- Repository reconnaissance: `AuthForm` already blocks login/register/forgot-password email submit whenever CAPTCHA is enabled but config is not ready or `captchaToken` is empty. `AuthTurnstile` previously handled Script `onReady`/`onError` and widget success/expired/error callbacks but had no app-side deadline for a top-level script with no callback.
- External research: current Cloudflare Turnstile docs recommend explicit client error/timeout recovery and document network/browser-extension failures; widget `timeout-callback` remains challenge lifecycle, not proof that a top-level script stall always resolves. Current Playwright Clock docs support deterministic timer advancement.
- Research limits: the 15-second value is a MoneyFlow UX deadline, not a Cloudflare SLA. No evidence supports CAPTCHA bypass, provider key changes, Supabase Auth policy changes, redirect/rate-limit/WAF changes or schema work in this slice.
- Security decision: timeout/error clears any stale token and never synthesizes a token. `AuthForm.captchaBlocked` remains unchanged and therefore stays the only client submit gate for these email-auth flows.
- Race decision: a mutable script-state ref is updated synchronously before React state; a watchdog fires only while the ref is still `loading`, so a later timer cannot overwrite `ready`; a late Script error after `ready` is ignored rather than clobbering successful readiness.
- Recovery decision: full-page reload is the only recovery action, avoiding a second custom script-loader/widget lifecycle. The action is a native button with focus-visible treatment and 44px minimum height.
- Browser decision: a pending intercepted Turnstile request simulates the exact no-ready/no-error stall; Playwright Clock advances the UX deadline without wall-clock sleep. Separate deterministic coverage proves a successful script/token before the deadline remains valid after the old timer would have fired.
