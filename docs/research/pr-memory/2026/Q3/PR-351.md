## Why --include-all was required

The Atoryn cleanup migration `20260812043219` carries a later timestamp than both
Recover migrations, so the CLI treats them as "to be inserted before the last
migration on remote" and refuses a plain push. This is expected, not a workaround:
no repair was used and no migration was reordered or edited.

## Read-back limitation

No arbitrary read-only SQL path exists from this environment (no `psql`, no stored
database password), so SECURITY DEFINER/INVOKER posture, `search_path`, RLS policy
bodies, indexes and constraints were **not** read from the live catalog. They rest
on CI pgTAP running these exact migrations against a real Postgres, plus live
anon-boundary probes. Supabase Postgres logs remain unreachable from this CLI.
