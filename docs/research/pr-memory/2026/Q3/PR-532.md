## Phase A evidence boundary

Current production root HTML explicitly contained an image preload for `/landing/moneyflow-quick-capture.svg`. Source places that screenshot in the story section after the hero and marks only index 0 `priority`; the other story images already lazy-load. Removing that priority removes unnecessary eager transfer without changing visible layout or content.

`MoneyFlowDashboard` already dynamic-imported the AddTransactionDialog and TransferDialog with `ssr: false`, but rendered both unconditionally with `open={false}` during initial hydration. Official Next guidance for deferred modals requires the dynamic component itself to be conditionally rendered so its JavaScript is requested on first open. The change preserves the same handlers, account/category inputs, mutation functions and transfer handoff.

`AppShell` also rendered its closed More sheet on every initial route. The bounded follow-up keeps the same `moreOpen` owner, paths, badges, account actions and ARIA state, but dynamically imports the shared `Sheet` implementation and does not render `MoreSheet` until `moreOpen` is true. This targets secondary sheet internals without splitting AppShell navigation or changing financial/data-flow ownership.

The connected Vercel tools expose build/request evidence but not the Speed Insights metric query; the local execution container cannot resolve `github.com` for a fresh checkout. Historical #403 figures therefore remain provenance only.
