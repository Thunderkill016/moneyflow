## Finding 2 — demo mutation persistence

A later P11 documentation head `caf933098121fa7ccf902055cb557e789fe23b30` again had a green Browser-smoke job conclusion, but raw logs exposed a first-attempt retry in `global-pfm-ux.spec.ts`: Quick Capture had already navigated away while `moneyflow-demo-transactions-v1` still lacked the new row.

Root cause in `src/hooks/use-transactions.ts`: demo mutations performed `writeStoredTransactions(...)` inside `setTransactions(current => ...)` updater functions, then returned `{ ok: true }` immediately. React updater functions are queued state calculations and must remain pure; navigation/unmount could occur before the updater side effect executed.

P11 now:

- uses `commitDemoTransactions(next)` to write localStorage synchronously before updating React state;
- derives add/delete/restore/split/update/bulk demo mutations from `readStoredTransactions()`;
- returns success only after the local ledger has been committed;
- refreshes demo transfer state after its existing synchronous transaction-store write;
- adds `src/lib/demo-transaction-persistence-contract.test.ts`, including a prohibition on `writeStoredTransactions` inside React state updater blocks.

This is a product correctness fix, not a timeout/retry workaround.
