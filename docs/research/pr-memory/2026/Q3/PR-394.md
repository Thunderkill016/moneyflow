Evidence then exposed a shared auth-field defect: `AuthPasswordField` implicitly labelled the password input with the entire wrapper, including the reveal-button name. `src/components/auth-password-field.tsx` now uses an explicit `<label htmlFor={id}>` for only the visible field label while keeping the reveal button as an adjacent sibling with its own accessible name, and `auth-form.module.css` preserves the existing field layout for the neutral wrapper.
- Research: W3C WCAG 2.2 SC 3.3.8 and its current Understanding document were used as primary authority. Password recall is a cognitive-function test, while password-manager autofill/copy-paste can provide a mechanism; OAuth may be an alternative; recovery/change steps remain inside the authentication boundary. Account creation is supporting evidence rather than the core conformance target. W3C form-label/APG guidance also prefers an explicitly associated `label`/`for` relationship for a form control; an adjacent action button remains a separately named control rather than content that should inflate the input name.
- Evidence boundary: the claim is scoped to MoneyFlow-owned browser mechanisms. The repository does not certify real Google OAuth or every Cloudflare Turnstile provider-managed challenge. `AuthTurnstile` uses `appearance: interaction-only`, but that source setting alone is not treated as provider accessibility proof.
