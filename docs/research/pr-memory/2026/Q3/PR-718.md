# PR #718 — Stored category icon/color honored on every surface + expanded icon set

- Date: 2026-09-26
- Change class: presentation-only at runtime, but doctor classifies
  Class 3 by path heuristic (`src/lib/transactions/**` financial-domain).
  No schema, no migration, no server action, no ledger semantics change.
- Affected capability or project boundary: the category *presentation*
  seam — `src/lib/transactions/category-presentation.ts` — plus every
  render site that previously derived icon/color from the static
  name-keyed `categoryMeta` record.
- Status impact: closes the "custom icon/color is stored but never
  rendered" defect surfaced by the category-system comparison; icon
  picker grows 10 → 34 options (`KNOWN_ICONS` 11 → 35, superset).
  Groups/subcategories and category merge remain open Class-3 work.
- Problem: `categories.icon`/`categories.color` were stored and editable
  in `/categories`, but pickers, transaction rows, dashboard, reports,
  trash and planning pages all resolved `categoryMeta[name]` — so the
  stored choice never appeared anywhere else, and any renamed or custom
  category fell back to a name lookup that could not match.
- Changed:
  - `resolveCategoryMeta(name, stored)` — stored icon/color wins, then
    the name-keyed default, then the generic "Thu nhập khác" meta.
  - `categoryMetaIndex(categories)` — `kind:name`-keyed map; category
    names are only unique per kind, so one name may legally exist as
    both an expense and an income category with different identities.
  - `categoryMetaFor(index, kind, name, fallback?)` — index lookup, then
    name-keyed default, then the caller's custom fallback, then generic.
  - `CategoryColor` literal union (8 palette values) + `isCategoryColor`
    — stored colors outside the palette degrade to the name-keyed
    default instead of emitting a class with no stylesheet owner.
  - The literal union is load-bearing for tooling, not just types:
    `check:code-css-ownership`'s scanner resolves `meta.color` through
    `addLiteralTypeValues`, so `transaction-icon ${meta.color}` keeps
    emitting all 8 palette tokens — baseline stays 211 with 0 stale.
    (Verified against a clean `61df72a` worktree: without the union the
    indirection through `categoryMetaFor` made 7 tokens look unemitted
    and the check demanded shrinking the baseline over live debt.)
  - `icons.tsx` +24 Vietnamese-relevant glyphs (coffee, fuel, bus, bike,
    parking, shirt, laundry, wifi, phone, tax, pill, baby, paw, study,
    gym, music, film, plane, gift, charity, ticket, briefcase, piggy,
    coins). Dialog `ICON_OPTIONS` = 34 with VN labels; `KNOWN_ICONS`
    = 35 (adds the internal `arrows` transfer glyph, deliberately not
    user-pickable). `COLOR_OPTIONS` typed `readonly [CategoryColor, …]`.
  - Migrated render sites: add/edit transaction dialogs (picker grid +
    quick chips), transactions workspace rows, timeline rows, trash
    rows, dashboard (`Chi theo danh mục` + recent rows via new
    `categories` prop on `DashboardLedgerColumn`), reports, budgets,
    commitments, income templates.
  - `/reports` and `/transactions/trash` loaders now also fetch
    `getCategoriesWorkspace()` (demo-aware) via `Promise.all` beside the
    existing calls; `TransactionsTrashPage`/`ReportsPage` take a new
    `categories` prop.
  - `Icon` falls back to `CircleHelp` for unknown names; demo-mode
    category saves stay state-only.
- Verified:
  - `category-presentation.test.ts` 5/5 (stored wins, palette guard,
    kind-keyed index, name/transfer/generic fallbacks);
    `verify:fast` green — knowledge, architecture, capabilities, lint
    (0 errors; one pre-existing unrelated warning), typecheck,
    `npm test` 1885/1885; `npm run build` 52 routes.
  - `check:migrations` 70 pinned; `check:css-ownership`;
    `check:dead-css` (all reachable); `check:code-css-ownership`
    (0 new, 0 stale, 211 remaining); `test:ci-policy` 191/191.
  - Browser (demo, :3105, Playwright): `/categories` edit dialog shows
    34 labelled icon options; switching "Ăn uống" to "Cà phê & đồ uống"
    and saving swaps the card glyph in place with a success toast.
    `/dashboard` transaction icons render; `/transactions`, `/timeline`,
    `/reports`, `/budgets`, `/commitments`, `/income-templates` all 200;
    no horizontal scroll at 390px; zero console/page errors.
- Remaining: director review + CI on the exact head; merge is the
  owner's call. Authenticated-mode icon persistence rides the existing
  `saveCategoryAction` path (unchanged).
- Production/provider evidence: none — not deployed, no schema.
- Superseded issue, roadmap or claim: "icons/colors are cosmetic-only
  and stored nowhere meaningful" — they are stored and now rendered
  consistently; what remains absent is groups/subcategories and merge.
- Lifecycle impact: surfaces that only have a transaction's category
  *name* (no categories list) still hit the name-keyed fallback —
  surfaces needing guaranteed stored identity must carry the categories
  list and build the index.

## Round 2 — director findings resolved (98409b8e)

- Archived-category regression: `FinanceWorkspace` loaders only returned
  active categories, so a historical row on an archived category lost its
  stored icon/color. Loaders now split one read into `categories`
  (active-only, pickers) and `metaCategories` (all rows, presentation
  index). Transactions/timeline index from `metaCategories`; the
  dashboard bundle stays active-only so the page fetches
  `getCategoriesWorkspace()` and passes it as `metaCategories` to the
  ledger column; commitments/income-templates/budgets skip the index
  entirely and resolve from feed-carried `categoryIcon`/`categoryColor`.
- Manage-page render gap: seeded "Thu nhập khác" stores icon `plus`,
  which `KNOWN_ICONS` lacked (rendered `spark` while other surfaces
  rendered `plus`). Icon contract now lives in
  `PICKABLE_CATEGORY_ICONS` (34) + `LEGACY_CATEGORY_ICONS` (`plus`) =
  `CATEGORY_ICON_NAMES`; `KNOWN_ICONS` derives from it plus `arrows`.
- Write-open contract: `saveCategoryAction` accepted arbitrary strings —
  writes now enforce `z.enum(CATEGORY_ICON_NAMES)` /
  `z.enum(CATEGORY_COLORS)`; `categoryTone` guards with
  `isCategoryColor` instead of probing stylesheet keys.
- Verified: `category-presentation.test.ts` 8/8 (adds archived-index,
  feed-carried + caller-fallback, writable-set pins); `verify:fast`
  green — `npm test` 1888/1888, typecheck, lint clean; `npm run build`
  52 routes; `check:migrations` 70 pinned; css-ownership/dead-css/
  code-css-ownership clean; `test:ci-policy` 191/191. Browser demo:
  all nine surfaces 200, zero console errors.
