# PR #627 — capability invocation log (P-A of #624 spec)

- Date: 2026-09-21
- Change class: Class 1 (bounded executable change inside the capability boundary)
- Affected capability or project boundary: `src/server/capabilities/invocation-log.ts` (new), `registry.ts`, `mcp.ts`, `src/app/api/capabilities/[id]/route.ts`, `src/app/api/mcp/route.ts`, `docs/agents/README.md`
- Status impact: megaplan A5 P-A implemented — the D5 minimal structured log now covers both transports uniformly
- Changed: every `runCapability` execution emits exactly one `capability_invocation` JSON line (`capabilityId`, `version`, `viewerId`, `clientId`, `transport`, `authorization`, `status`, `errorCode`, `durationMs`) via `console.info`; emission wraps the whole call including `not_found` and write-gate rejections, is fail-safe, and is injectable via `onInvocation` for tests. Transports pass `transport: "api"|"mcp"`; pre-execution refusals (401/403/429) emit `status:"rejected"` records at the route — `capabilityId` known on REST (URL param), null on MCP (unknowable pre-parse). Arguments, outputs and token material are never logged (spec S3; a test asserts no input substring appears).
- Verified: `npm test` 1421/1421 (5 new tests); typecheck; lint 0 errors (1 pre-existing warning); build clean; check:knowledge/architecture/capabilities green.
- Remaining: CI provider lanes on the exact head; no durable `capability_invocations` table (deferred per spec until a named trigger).
- Production/provider evidence: none yet — log lines verified in unit-test output; platform log ingestion on Vercel follows the same `console` convention as `[client-error]`.
- Superseded issue, roadmap or claim: none.
- Lifecycle impact: adds telemetry emission only; no schema, contract, UI or capability-surface change.

## Boundaries

- Log is platform-log forensics only; no durable table, no Activity-feed surface (both deferred by the #624 decision record).
- `durationMs` measures `runCapability` execution; route-level rejections emit `durationMs: 0`.

## Evidence limits

- Emission asserted through injected `onInvocation` collectors and a mocked `console.info`; real Vercel log ingestion is the same `console` channel as existing `[client-error]`/`[capability-api]` lines but was not exercised against a live deployment.
