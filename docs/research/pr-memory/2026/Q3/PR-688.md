# PR #688 — Pauseable delete-undo window + per-row busy state

- Date: 2026-09-23
- Change class: Class 2 (bounded UI/flow on `/transactions`; no migration, schema, RPC or provider change)
- Affected capability or project boundary: `src/components/transactions/transactions-workspace.tsx`, `src/hooks/use-transactions.ts`, `src/components/ui/toast.tsx`, `src/components/layout/app-shell.tsx`, new `src/lib/pausable-countdown.ts` + `src/lib/mutating-ids.ts`, contract pins in `src/lib/ui-phase5-transactions-contract.test.ts`.
- Status impact: quality-audit B3/B4 gaps on the ledger delete-undo toast are implemented: the 8s undo countdown pauses on hover/focus, unrelated notices no longer kill a live undo, "Hoàn tác" gates on its own restore, and single-row mutations freeze only their own row.
- Changed: `ToastRegion` reports a combined hover/focus hold via `onHoldChange`, forwarded by `AppShell` as `onNoticeHoldChange`. The workspace runs two pausable countdown slots — transient notice text vs the undo window — driven by pure `Countdown` math (`startCountdown`/`pauseCountdown`/`resumeCountdown`/`pausedCountdown`). `pendingUndo` now carries `{ snapshots, message }`; `showNotice` only replaces the text slot, `expireNotice` resurfaces the undo message while its window is open, `expireUndoWindow` drops the snapshots and clears the toast only if the undo text is still showing. In `use-transactions`, `deleteTransaction`/`restoreTransaction`/`updateTransaction` mark a new `mutatingIds` set instead of `isMutating`; bulk and form-level ops keep the global flag. Row controls use `rowBusy(id) = isMutating || mutatingIds.has(id)`; the undo action disables on its own snapshot ids only; the delete-confirm dialog spins/locks on `deleteTargetBusy`.
- Verified: `npm run typecheck` clean, `npm run lint` 0 errors (1 pre-existing warning in `quick-add-defaults.test.ts`, untouched), `npm run test` 1721/1721 (13 new pure-logic/contract-pin tests), `check:knowledge`, `test:ci-policy` 191/191, `check:css-ownership`, `check:architecture`. Browser smoke and visual audit delegated to CI lanes.
- Remaining: owner review/merge decision only. The `hold` signal relies on mouseenter/leave + focusin/out synthesis; a toast mounting directly under a stationary pointer may not fire `mouseenter` in every browser — graceful degradation (countdown runs normally) rather than a stuck state, since a held region arms countdowns paused and releases on leave/blur.
- Production/provider evidence: none (client-only interaction layer; production verification remains an owner decision post-merge).
- Superseded issue, roadmap or claim: none — quality-audit gap closure.
- Lifecycle impact: any future timed toast needing pause-on-hold can reuse `onNoticeHoldChange` + `src/lib/pausable-countdown.ts`; `mutatingIds` is available to other `useTransactions` consumers if inbox/dashboard later want per-row busy gating.
- Rollback: revert the branch — server actions, soft-delete semantics and ledger contracts are unchanged.
