# PR #712 — Day-grouped recent list on dashboard

- Date: 2026-09-24
- Change class: Class 2 (user-interface surface; no schema, no migration —
  CI selects browser smoke + responsive audit lanes)
- Affected capability or project boundary: `DashboardLedgerColumn` recent-
  activity panel (`src/components/dashboard/dashboard-overview-sections.tsx`),
  `src/lib/dashboard-recent-groups.ts`, `src/lib/relative-date.ts`,
  `src/lib/transaction-status.ts`, plus the four former producers of the
  date-label grammar (`server/finance.ts`, demo fixtures, reconciliation,
  bulk date change) and the seven writers of `relativeDate` statuses.
- Status impact: the dashboard's latest-5 list groups by calendar day with
  derived date headers — closing research gap G4 — while optimistic/
  committed operation states stay visible at row level and can never
  masquerade as a day header or vice versa.
- Changed:
  - `groupRecentTransactionsByDay(rows, today)` groups by `occurredOn`,
    sorts groups newest day first (a backdated optimistic prepend cannot
    pin a stale day to the top), preserves row order inside each group.
  - Headers render `formatRelativeDate(occurredOn, today)` inside
    `<time dateTime>` — never `relativeDate`, which is overloaded with
    operation statuses.
  - `formatRelativeDate` extracted from `src/server/finance.ts` into
    `src/lib/relative-date.ts` (explicit `today` param, unparseable input
    returns the raw string); replaces the duplicate grammars in
    `demo/transaction-fixtures.ts`, `reconciliation.ts`
    (`adjustmentRelativeDate`) and `transaction-review.ts`
    (`bulkOccurredOnLabel` kept as a delegating alias).
  - `src/lib/transaction-status.ts` owns the status vocabulary
    (`TRANSACTION_STATUS.saving/edited/completed` +
    `isTransactionStatusLabel`); all seven producers write the constants.
    A row renders the status inline only when the predicate confirms a
    real state — a stale persisted "Hôm nay" is date-shaped and never
    shows as a status.
  - `.transaction-time` column removed; `.dayGroup`/`.dayLabel`/
    `.transactionStatus` are CSS-Module-owned (baseline may only shrink —
    `transaction-time` allowance dropped).
  - `DASHBOARD_UPGRADE_RESEARCH_2026.md` marks G1–G3 as already shipped
    (stale doc), G4 as implemented here pending merge, G5 open.
- Verified:
  - `typecheck`, `npm test` 1857/1857 (5 grouper + 3 predicate tests incl.
    interleaved-date and stale-persisted-label cases), `lint` 0 errors,
    `build` 52 routes, knowledge/architecture/css-ownership/dead-css/
    code-css-ownership, `test:ci-policy` 191/191.
  - Browser (demo, :3100): headers `Hôm nay`/`Hôm qua`/`21 thg 9` with
    `dateTime` attributes; injected rows cover all three cases — `pending:`
    under its real day with "Đang lưu…" at row level, stale "Hôm nay"
    suppressed, "Vừa xong" shown; zero console errors.
  - Technical director (codex exec) ran three review rounds on the diff;
    reproduced the stale-label defect end-to-end before the predicate fix.
- Remaining: CI green on the exact head is required; merge is the owner's
  call. G5 (hydration/perf) stays measurement-gated.
- Production/provider evidence: none — not deployed, no schema.
- Superseded issue, roadmap or claim: implements gap G4 of
  `DASHBOARD_UPGRADE_RESEARCH_2026.md`; the doc's earlier claim that G1–G4
