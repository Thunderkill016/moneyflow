# PR-712 — Day-grouped recent list on dashboard

**Date:** 2026-09-24
**Branch:** `feat/dashboard-g1-g3`
**Change class:** 2 (user-interface surface)
**Lifecycle state:** implemented + locally verified; director round-2 findings fixed; awaiting CI and owner merge decision

## What changed

- `src/lib/relative-date.ts` (new): `formatRelativeDate(date, today)` — single
  source for the ledger's day label ("Hôm nay" / "Hôm qua" / "21 thg 9"),
  extracted from `src/server/finance.ts` so client code can derive labels
  without importing a server module or reading a client clock. Unparseable
  input returns the raw string (parity with the reconciliation fallback).
- `src/lib/dashboard-recent-groups.ts` (new): `groupRecentTransactionsByDay
  (rows, today)` — pure grouper keyed on `occurredOn`; label derived via
  `formatRelativeDate`, **never** from `relativeDate` (which carries
  optimistic statuses "Đang lưu…"/"Vừa sửa"); groups sort `occurredOn`
  descending so an interleaved/backdated optimistic row lands in its own day
  group instead of reordering the list; rows keep input order within a group.
- `src/components/dashboard/dashboard-overview-sections.tsx`: latest-5 list
  renders day groups (`<time dateTime={occurredOn}>` header per group);
  per-row `transaction-time` column removed; a row whose `relativeDate`
  differs from the derived date label keeps it as an italic status line so
  the pending signal G4 would have dropped stays visible.
- `src/components/dashboard/dashboard.module.css`: `.dayGroup` / `.dayLabel`
  / `.transactionStatus` as CSS-Module-owned classes (ownership check forbids
  new baseline debt); row grid tightened 4→3 columns; `transaction-time`
  rules removed (dead class, baseline allowance dropped).
- `src/server/finance.ts`, `src/lib/demo/transaction-fixtures.ts`,
  `src/lib/reconciliation.ts`, `src/lib/transaction-review.ts`: all four
  duplicate copies of the label grammar replaced by `formatRelativeDate`
  (`bulkOccurredOnLabel` kept as a delegating alias — semantic name + test).
- `docs/research/DASHBOARD_UPGRADE_RESEARCH_2026.md`: status block added —
  G1/G2/G3 were already merged when the doc listed them as open gaps;
  G4 ships here; G5 remains measurement-gated.

## Director review — round 2 findings and fixes

1. **Header could read an optimistic status.** `relativeDate` is overloaded:
   `optimistic-transactions.ts:55` writes "Đang lưu…", `:98`/`:133` write
   "Vừa sửa". First-row labeling meant a whole day group could display a
   status. → Headers now derive from `occurredOn` + workspace `today` via
   the shared helper; the status still renders per-row (italic `<small>`)
   so the pending signal is not lost.
2. **`Map` grouping reordered interleaved input.** With a backdated
   optimistic row prepended, `23 → 25 → 23` produced `23 → 25` groups with
   the second 23-row pulled forward — the claimed "order-preserving"
   contract was false. → Contract made explicit: groups sort by `occurredOn`
   desc (correct "recent" semantics), row order preserved within each
   group; interleaved test pins it.

## Director review — round 3 finding and fix

3. **Stale persisted labels were misread as statuses (P2).** The first
   status-detection compared `relativeDate !== formatRelativeDate(...)`,
   but demo mode *persists* `relativeDate` in localStorage: a row saved
   "Hôm nay" yesterday re-opens under the "Hôm qua" header while the row
   still carries "Hôm nay" — a stale date label, not an operation status.
   → New `src/lib/transaction-status.ts` owns the status vocabulary
   (`TRANSACTION_STATUS.saving/edited/completed` + `isTransactionStatusLabel`);
   all 7 producer sites write the constants and the row renders a status
   only when the predicate confirms a real state. Stale date labels are
   date-shaped, never status-shaped — verified live with injected rows.
   Docs/PR body updated to match the real contract (P3).

## Decisions

- Group key is `occurredOn`, not the display string — one calendar day can
  never split into two groups even if labels ever diverge.
- Day-group order is `occurredOn` desc, not input order — a backdated
  optimistic prepend must not pin a stale day to the top of "recent".
- Header derives the date label; per-row status renders only when
  `relativeDate` differs from the derived label (i.e. it is a state, not a
  date).
- No data/loader changes; presentation + shared-helper consolidation only.
