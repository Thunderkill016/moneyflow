## Why the mechanism, not just the symptom

MF-04's audit finding was that whole surfaces render unstyled. The reason it
shipped is that no gate asked the code → CSS question: `check:dead-css` asks
CSS → code and `check:css-ownership` polices the cascade. An unstyled element
still has a box, still fits the viewport and still has an accessible name, so the
responsive audit could not see it either.

The gate therefore landed before the migration, with the current debt frozen as a
reviewed baseline that can only shrink.

## Ownership requires an unconditional owner

Review found the first implementation flattened the bundle into a set of class
names, so `.dashboardHash .secondary-button` certified `.secondary-button` for
every surface that emits it elsewhere. A class is now owned only when a selector
can match it without requiring another application class the checker has not
proven; contextual owners are reported and counted as debt.

Shrink-only is measured against approved git history rather than the working-tree
baseline, so adding a broken class plus a matching allowance now fails.

Three approaches to reading ownership were tried and rejected, and the reasons
are recorded in the script so they are not rediscovered:

1. a hand-written Tailwind allowlist — rejected outright;
2. compiling `globals.css` through postcss — disagreed with the real pipeline,
   because `@import "shadcn/tailwind.css"` does not resolve;
3. scanning all of `.next` — contaminated by `.next/dev/**`, which still held
   chunks from a retired stylesheet and made a dead class look owned.

CSS escaping mattered: unescaping `.hover\:bg-muted` and indexing the
post-variant segment moved the owned set from 219 to 1210 tokens.

A CSS Module's local class is deliberately not an owner for a literal class name,
since the build hashes it.

## Onboarding

Before, on a production build: transparent card, `padding: 0`, no radius, no
shadow, full-bleed 1280px on desktop. After: painted surface, 20–32px padding,
18px radius, shadow, 358px on phone and 544px bounded on desktop, dark inherited
from `html[data-theme]`, zero overflow in all four states.

Class attributes only — no logic, no copy, no flow change.

## Boundary

The gate proves presentation ownership. Runtime measurement proves rendering.
Neither substitutes for the other, and both were produced here.

## Finding recorded for follow-up

`globals.css` has no `@theme` block, so Tailwind v4 generates nothing for
`bg-background`, `text-foreground`, `border-border` or `bg-muted`, which Button,
Card, Dialog, Sheet, Toast and TextField emit — 72 of the remaining entries. This
is a static ownership fact from the bundle; the visual consequence has not been
measured and should be before acting.
