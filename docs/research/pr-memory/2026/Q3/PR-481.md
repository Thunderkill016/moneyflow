# PR #481 — ci: stop letting a stale draft flag skip the contracts

- Date: 2026-08-26
- Change class: Class 1 — bounded change to `.github/workflows/ci.yml` only, with straightforward rollback. No application code, schema, migration, RPC, RLS, provider or financial-semantics change.
- Affected capability or project boundary: CI gate selection. It changes **when** jobs run and never **which** checks are required; branch protection, required checks, workflow permissions and `CODEOWNERS` are untouched.
- Status impact: candidate until merged. It closes a false-green path rather than adding capability, so no capability truth changes — but it does change how much every other gate can be trusted.
- Lifecycle impact: completes current slice. Issue #417 is delivered in this same PR, which carries its own post-merge convergence: the board projection names PR #481, no successor slice is promoted, and projected current memory is updated here. `plan:resolve` intentionally reports NOT READY while this is unmerged.
- Why now: the owner instructed on 2026-08-26 to remove blockers, do what is reasonable and drop what no longer applies. I had previously recorded #417 as needing owner permission; re-reading it, the fix touches neither permissions nor required checks, so that was my own over-caution rather than a real boundary.
- The defect: eight jobs gated on `github.event.pull_request.draft`, read from the run's **own event payload**. Opening a pull request as a draft and marking it ready seconds later delivers both events; the concurrency group cancels one; when the survivor is the draft-event run it skips every shard and reports `success`. A job skipped by `if:` reports Success and does not block merge even when the check is required, so such a head could merge with the knowledge contract, migration identity contract, CI classification contract and diff hygiene never having executed. #417 records the observed instance on PR #416 head `9e77ad86`.
- Direct evidence the defect bites, from this session rather than from the issue: every pull request opened today carried an empty `chore: re-trigger checks on ready head` commit purely to force a non-draft run. That workaround is what this change removes.
- Changed: all nine occurrences of the draft condition deleted, leaving `needs.classify.outputs.*` path gates and `always()` where they already were. A comment at the top of the workflow records the race, the observed instance, and an instruction not to reintroduce a draft condition, because any fix that trusts the event payload has this race again.
- Alternatives rejected, each from #417's own list: **narrowing the concurrency group** leaves two runs posting conclusions for one head, which is ambiguous rather than fixed. **Reading live draft state from the API** in `classify` and gating on that output is the fix I would otherwise have written, and it is refused only because it needs a `pull-requests: read` permission and `AGENTS.md` forbids changing workflow permissions inside feature work. **Dropping the condition from `verify_policy` alone**, the issue's middle option, closes the contract hole but not the code hole: `verify` keeps its own draft gate, so a code pull request readied quickly could still merge with static, tests and build skipped.
- Cost, stated rather than glossed: draft pull requests now run the checks their changed paths select, where before they ran none. For a docs-only draft that is the cheap policy shard; for a draft touching UI it is the full set including the roughly 11-minute cross-device audit. That cost is the point — a draft that has not been verified should not be able to become a merged head that was never verified.
- Verified: `test:ci-policy` (**197 pass**), `check:knowledge`, and the workflow parses as valid YAML. `scripts/` and `docs/engineering/RISK_PROPORTIONAL_DELIVERY.md` were grepped to confirm no other file encodes the draft rule, so removing it here does not leave a contradicting statement elsewhere.
- Limitation, not a pass: the fix can only be proven by the provider running it. Local checks confirm the workflow is well-formed and the policy contract still passes; they cannot demonstrate that a draft→ready race now behaves correctly. This pull request was deliberately opened **non-draft**, so its own run does not exercise the race either. The honest proof is the next pull request opened as a draft, which should show real shard results instead of skips.
