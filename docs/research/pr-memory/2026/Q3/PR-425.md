- Correction to my own first measurement, made before merge: I counted sixteen destinations by grepping hrefs out of `src/lib/nav-ia.ts` and concluded that a quarter of the navigation went to Inbox, imports and rules. That was wrong. It flattened a deliberately tiered information architecture and made a well-made thing look broken. The primary navigation is **four items** — Tổng quan, Giao dịch, Nhập nhanh, Tài khoản — and Inbox, rules, imports and timeline are already demoted to More → Nâng cao under a source comment reading "so the app feels focused". The navigation and the product law do not contradict each other, and **no navigation change is recommended**. The weaker point that survives is that export has no destination of its own, though it is named inside the Báo cáo description and lives at `/settings/export`, so it is reachable rather than hidden; that is a question for the owner, not grounds for an agent to edit a working IA. What does hold from the measurement: the full surface is 39 routes, with four capture surfaces and two ledger views. Documentation had reached 335 files and 3.8 MB, including five Webflow design-category studies, Framer and UXPilot corpus inventories, and a readiness report from another product's agent framework.
- Two candidates deliberately stayed: `CALM_LEDGER_V2.md` and `SIGNAL_LEDGER_V3.md` are superseded by every documentation argument but are load-bearing for code — `SIGNAL_LEDGER_V3.md` is read directly by three files under `src/` — and a first attempt at moving them broke two tests. Archiving them requires changing those tests, which deserves its own review. The generalisable lesson is recorded in both the archive README and the assessment: inbound **code** references must be checked, not only documentation links.
- Process observation, included because minimalism has to apply to how the project runs: every change pays the same paperwork tax whether it is one line or a subsystem — 130 memory records, 60 completed packets, plus four contract gates. What that machinery bought during the session producing this document is stated rather than assumed: two pull requests rejected for missing their own memory record, a CSS class with no presentation owner, a 44 px target that would have shipped, and a claimed 99 ms performance improvement that was noise. The proposal is therefore not to dismantle it but to let paperwork scale with the risk classes the gates already use.
