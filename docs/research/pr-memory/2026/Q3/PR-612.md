## Boundaries

- The app never mints authorization codes or tokens — it only records the consent decision; Supabase issues credentials. Consent decision is explicit; no auto-approve path exists.
- `redirect_url` returned by approve/deny comes from Supabase's validated client registration — the app does not accept arbitrary redirect targets from the browser.
- Demo viewers can never reach the consent decision — `viewer.isDemo` redirects to `/login` like an unauthenticated user.
- `authorization_id` travels through the `next` login param and hidden form inputs; it is an opaque request handle, not a credential.
- Client registration stays manual (`allow_dynamic_registration = false`) — no open DCR attack surface.
