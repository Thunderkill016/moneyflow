## Privilege decision recorded

`restore_user_archive` and `remove_archive_restore_batch` are SECURITY DEFINER,
proven rather than inherited. Fifteen of the nineteen tenant tables deliberately
have no INSERT grant and no INSERT policy for `authenticated`, because live
financial writes must pass through the reviewed RPCs that enforce transfer
balance, split exactness, entry sign and category kind. SECURITY INVOKER would
require granting the browser direct INSERT on `financial_transactions` and
`transaction_entries`, permanently bypassing those invariants. DEFINER confines
the elevated right to two reviewed functions.

## Named fidelity limitations

`inbox_rules.version`/`created_at`/`updated_at` and
`inbox_candidates.fingerprint`/`fingerprint_version` are trigger-owned and cannot
be preserved; `applied_rule_version` is realigned to the restored rule because
the evidence trigger demands an exact match. Rule behaviour and all financial
state are preserved exactly. Archived ids are preserved, so a restore beside a
live source tenant is refused.

## Not claimed

- P2 Recover is not accepted: no raw-file ingress, no UI.
- Neither archive migration is live in production.
