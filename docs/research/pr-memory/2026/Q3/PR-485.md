- Lifecycle impact: completes current slice. The work is registered by the repository audit rather than by an issue, and this PR carries its own post-merge convergence: the board projection names PR #485, no successor slice is promoted, and projected current memory is updated here. `plan:resolve` intentionally reports NOT READY while this is unmerged.
- The gap: `FinancialReport.trend` has always returned `{ key, label, income, expense }` per bucket, and the page drew only `expenseBar` — `incomeBar` existed nowhere in the component or the stylesheet. Half of that computation was discarded on every report.
- Changed: a second bar per column sharing one scale; a text legend above the chart; the `role="img"` label, the per-column `title` and the screen-reader description list all now report both series; the empty state keys on any activity; `.trendBars` gains a gap so the two bars do not touch.
- Four traps, each pinned by a test rather than assumed. **Shared scale** — scaling each series to its own maximum would draw a 300.000 ₫ expense and a 20.000.000 ₫ salary at the same height, reversing what the chart says about where money went; the test counts `/ trendMax)` uses and separately asserts the old expense-only scale is gone rather than merely unused. **Empty state** — it keyed on expense alone, so a month where salary had arrived and nothing was spent yet hid real recorded data behind "chưa có khoản chi". **Screen-reader parity** — the chart is `role="img"` described by that list, so omitting income would have made the accessible version say less than the picture, an accessibility regression introduced by an otherwise accessibility-friendly chart. **Colour alone** — the product rule is that money must not depend on colour, so the legend names both series in text with the swatch beside the word rather than replacing it.
- The first test in the file asserts the trend genuinely carries non-zero income for a realistic fixture, so the five source-level assertions after it cannot pass vacuously against a chart drawing nothing.
- Verified: `typecheck`, `lint` (0 errors), `test` (**1184 pass**, +6 new), `check:architecture`, `check:css-ownership`, `check:code-css-ownership` (after a real build, as that gate requires — the new classes have a real CSS Module owner and add nothing to the presentation-ownership baseline), `check:knowledge`, `test:ci-policy`, `check:migrations`, and `npm run build` with `NEXT_PUBLIC_APP_MODE=authenticated`.

The contract tests read the component source and stylesheet; they prove the markup and styles are present, not that the chart renders correctly in a viewport.
- Remaining: from the same audit, the product has **no offline capability at all** — `public/sw.js` handles push notifications only, with no `fetch` handler, no cache and no offline document, and `navigator.onLine` appears nowhere in `src/`, so the app cannot tell it has lost connectivity until a save fails. That is the largest remaining gap and needs its own scope. Receipt attachments do not exist and are **not** recommended, since they need blob storage and therefore a recurring per-user cost. The trend still shows no net line and no drill-down, both out of scope here.
