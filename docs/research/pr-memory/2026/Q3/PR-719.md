# PR #719 — Two-up secondary actions on phones instead of full-width stack

- Date: 2026-09-25
- Change class: bounded UI/CSS (Class 2-presentational). No JS/TSX,
  no schema, no server action. Heuristic doctor class may differ off
  path keywords; actual diff is CSS-module only.
- Affected capability or project boundary: phone-width layout density
  of secondary action groups across 8 CSS modules; desktop (≥761px)
  behavior unchanged.
- Superseded issue, roadmap or claim: closes the "mobile secondary
  actions stack one full-width row each" finding from the whole-app
  design comparison (2026-09-25). The comparison also logged a desktop
  `/capture` narrow-column nit and missing whole-app dark-mode sweep as
  lower-priority leftovers.
- Context: at ≤760px the shared `SecondaryHeader` actions and
  per-page action groups each rendered `flex: 1 1 180px` or
  `grid-template-columns: 1fr` — on a 390px phone that produced one
  ~50px full-width row per button (~250px before content on /inbox).
- Changed (CSS only, +78/−15):
  - `secondary-layout.module.css`: `.actions`/`.sectionAction` →
    `repeat(2, minmax(0, 1fr))` grid at ≤760px; `.summary` 2-up at
    ≤480px; 1-col fallback for all three at ≤340px.
  - `transactions-workspace.module.css`: `.headingActions` → 2-col grid
    at ≤760px, 1-col at ≤340px.
  - `planning-workspace.module.css` (card actions ≤700px),
    `rules-page` (incl. `.dialogFooter`), `imports-page`,
    `import-preview-page`, `direct-csv-import-page`,
    `inbox-bulk-bar` (`.actions`/`.buttons`): same 2-col / ≤340px
    fallback pattern — the precedent already set by
    `categories-page.module.css` (2-col ≤560px, 1-col ≤380px).
- Cutoff choice: 340px so the common 360px Android width still gets
  2-up; 320px minimum target gets 1-col.
- Verification:
  - Browser sweep 10 routes × {390,360,320,1440}px: 0 console errors,
    0 horizontal scroll, no clipped labels, all action targets 44px.
  - Interactions: "Chia khoản chi" dialog open/close at 390px, kind
    chip `aria-pressed` filter, inbox bulk bar 2-up/1-col boundary.
  - Independent design evaluator: PASS (designQuality 8, originality
    7, craft 8, functionality 9; responsive/a11y/financial-semantics/
    consistency gates all pass); `npm run design:check` passes on the
    evaluation JSON. Two P3 non-blocking notes: pre-existing 96×16px
    "Tùy chọn xuất" inline-link target on /reports; odd-count grids
    leave a half-width last cell (inherent, cosmetic).
  - Gates: lint (0 errors), typecheck, build 52 routes, 1880/1880
    tests, css-ownership, dead-css, code-css-ownership (0 new/0 stale,
    211 baseline), ci-policy 191/191, knowledge.
