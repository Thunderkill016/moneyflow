# PR #687 — Keyboard navigation layer for the ledger workspace

- Date: 2026-09-23
- Change class: Class 2 (bounded UI interaction layer on `/transactions`; no migration, schema, RPC or provider change)
- Affected capability or project boundary: `src/components/transactions/transactions-workspace.tsx` (+ its CSS module), new `src/lib/keyboard.ts` shared helpers, new `src/lib/transactions/keyboard.ts` mapping, `src/lib/inbox/keyboard.ts` re-export, tests in `src/lib/transactions/keyboard.test.ts`.
- Status impact: the ledger list was the only dense workspace with no keyboard path — rows were non-interactive `<article>`s and only icon buttons were tabbable. Power users can now walk, select, edit, delete and add without the mouse, mirroring the shipped inbox pattern.
- Changed: `j`/`k` move a focused-row index over `listWindow.visible` (the flat display order the day groups render) with `scrollIntoView({block:"nearest"})`, a `.focused` inset bar (inbox parity) plus a forced-colors `Highlight` outline, and `aria-current="true"` on the focused row. `Enter`/`e` follows each row's own click path exactly — recurring rows route to `/commitments` like the lock link, split rows get the explanatory notice via `handleEditClick`, everything else opens the edit dialog. `x` reuses `toggleTransactionSelection` (inert while the review feature is off or a mutation is in flight, matching the disabled checkbox). `Delete`/`Backspace` call `handleDelete` → existing `SecondaryReviewDialog` confirm → 8s undo. `n` opens the add dialog (timeline variant routes to `/capture/quick`, matching its primary action). `/` focuses the toolbar ledger search (marked `data-app-search`, same contract as the app-shell topbar input). `Esc` peels search → selection → row focus via the pure `resolveLedgerEscape`. All shortcuts are guarded by `isEditableKeyboardTarget`, inert while any workspace dialog is open, and `Enter`/`e` defer to a focused control's native activation via `isInteractiveKeyboardTarget`. The generic guards moved from `src/lib/inbox/keyboard.ts` into `src/lib/keyboard.ts`; the inbox module re-exports them so its call sites and tests are untouched.
- Verified: `npm run typecheck` clean, `npm run lint` 0 errors (1 pre-existing warning in `quick-add-defaults.test.ts`, untouched), `npm run test` 1689/1689 (8 new pure-logic/contract-pin tests), `check:knowledge`, `test:ci-policy` 191/191, `check:css-ownership`, `check:architecture`. Browser smoke and visual audit delegated to CI lanes.
- Remaining: `x` is intentionally inert when `reviewFeatureAvailable` is false (the selection UI does not exist there). The no-dep-array keydown subscription was chosen over inbox-style refs so the handler always sees the current `filterKey`-scoped selection setter; inbox keeps its own wiring. `/` is ledger-local — a global `/` search shortcut in `app-shortcuts.ts` was deliberately not added.
- Production/provider evidence: none (client-only interaction layer; production verification remains an owner decision post-merge).
- Superseded issue, roadmap or claim: none.
- Lifecycle impact: any future workspace (e.g. commitments, accounts) can reuse `src/lib/keyboard.ts` plus a small local action map instead of re-deriving guards; if a third consumer appears, consider whether `resolveLedgerEscape`-style ordering belongs in the shared module too.
