## Architectural decision recorded

`export_user_archive()` is **SECURITY INVOKER**, not SECURITY DEFINER. Every one
of the nineteen tenant tables has RLS with an owner-based SELECT policy for
`authenticated`, so invoker rights make tenant isolation structural: RLS filters
rows to the caller regardless of the function's own predicates. SECURITY DEFINER
would move that guarantee into the function's own correctness and grow the
reviewed privileged inventory that `security_definer_contract.test.sql` pins at
34. The function takes no arguments, so tenant spoofing is impossible by API
shape.

It is deliberately VOLATILE rather than STABLE: each call mints a fresh
`archive_id` and `produced_at`, so STABLE would be a false promise to the
planner. Read-only behaviour is proven by asserting row counts are unchanged
across a call, not by the volatility label.
