# PR #501 — pin every action, and gate it

- Date: 2026-08-27
- Change class: Class 1 — two workflow files pinned and one new repository contract with unit tests. No application code, schema, migration, RPC, RLS, provider or financial-semantic change; nothing in `src/` is touched.
- Affected capability or project boundary: GitHub Actions supply-chain pinning and the always-run policy gate.
- Status impact: candidate until merged. On merge the nightly UI audit can start for the first time since 2026-07-31, and the health monitor added by PR #500 can run at all.
- Lifecycle impact: authority transition. No slice is completed or promoted — none is registered. It carries the board's move to PR #500's merged commit `4261cc39`, the transition this PR is the same-PR projection for.
- Found by running the thing rather than trusting it. After PR #500 merged, dispatching the health monitor failed in seven seconds: `all actions must be pinned to a full-length commit SHA`. The repository setting enforces this at action resolution, before any step runs. My workflow was wrong — and fixing it uncovered something larger.
- **`ui-audit-nightly.yml` had not run since 2026-07-31.** The same one-line defect was already merged there. Every scheduled run from 2026-08-03 to 2026-08-27 failed in about seven seconds — 19 consecutive failures — which means 27 days of "nightly Firefox coverage" never happened. Nothing said so, because the rule lives only in a GitHub repository setting and no contract in the repository checked it before merge. It passed once, survived nearly a month, and I then reproduced it exactly in PR #500.
- Changed: `.github/workflows/ui-audit-nightly.yml` and `.github/workflows/health-monitor.yml` pinned to the same SHAs the repository's other workflows already trust — no new SHA introduced; `scripts/check-workflow-pins.mjs` and `scripts/check-workflow-pins.test.mjs` (8 tests) added; `check:workflow-pins` added to `package.json` and the test registered in `test:ci-policy`, which runs on every pull request.
- The contract catches more than the tag form that caused this: a branch ref (`@main`, `@master`), a **short** SHA (resolves today, can collide later, and the setting requires 40 characters), and a `uses:` with no ref at all. Local `./…` and `docker://…` uses are exempt because they are not fetched by ref. Commented-out examples are ignored so a documented sample cannot fail a build.
- One test asserts every workflow in this repository is pinned, not merely that the rule is implemented. That is the assertion that was untrue for 27 days, and a rule with no repository-wide assertion behind it is how the first one survived.
- Verified: `node --test scripts/check-workflow-pins.test.mjs` **8 pass**; `npm run check:workflow-pins` PASSED across 6 workflow files; `npm run test:ci-policy` **217 pass** (+8); `lint`, `typecheck`, `check:knowledge` exit 0.
- Proven to fail, not only to pass: restoring the exact line that killed the nightly audit (`actions/checkout@v4` at `ui-audit-nightly.yml:21`) turned the contract red with that file and line named, exit 1. It was then restored.
- Remaining: the health monitor is **not yet proven to run green after pinning** — `workflow_dispatch` requires the workflow to exist on the default branch, so it can only be exercised after merge, and it will be, with the real result reported rather than inferred from a green CI. The nightly audit likewise cannot be confirmed until its next scheduled run. This contract governs pinning only; it says nothing about whether a pinned SHA is the version anyone intended, and nothing keeps those pins current — there is no automation refreshing them.
- Production/provider evidence: not applicable. No production read or write; the failing evidence is GitHub Actions run history for this repository.
- Snapshot update: `docs/research/CURRENT_PROJECT_MEMORY.md` and the board move to PR #500's baseline `4261cc39` and carry the PR #501 projection. No capability row changes.
- Superseded issue, roadmap or claim: supersedes the standing assumption that a nightly UI audit was running. It was scheduled and it was failing, which is not the same as running, and the difference went unnoticed for 27 days.
