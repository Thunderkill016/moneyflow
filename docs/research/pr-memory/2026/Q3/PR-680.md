# PR #680 — Advisory ledger-duplicate review strip on /transactions

- Date: 2026-09-22
- Change class: Class 2 (bounded UI/flow — one review strip inside the existing transactions workspace)
- Affected capability or project boundary: `src/lib/ledger-duplicates.ts` (new pure detector: `findLedgerDuplicateGroups`, `LedgerDupeRow`, `LedgerDuplicateGroup`, habit/cadence constants), `src/lib/ledger-duplicate-dismissals.ts` (new client-local store keyed `moneyflow-ledger-dupe-dismissals-v1`, mirroring `planning/recurring-dismissals.ts`), `src/lib/delete-account.ts` (+ test — the new key joins `LOCAL_DATA_STORAGE_KEYS`), `src/components/transactions/transactions-workspace.tsx` (strip state, dismissal loading, `dismissDupeGroups`, `formatDayMonth`, the `ledger-dupe-strip` section between the toolbar and selection toolbar), `transactions-workspace.module.css` (`.dupeStrip`/`.dupeSummary`/`.dupeGroups`/`.dupeGroup`/`.dupeRow` family, responsive padding-inline and forced-colors entries).
- Status impact: committed ledger rows now surface as "N giao dịch có vẻ trùng — Xem lại" when they share account + kind + amount + normalized note inside the ±2-day near-match window from #668. Advisory only — no auto-delete/merge/approve; the sole mutation is the existing `handleDelete` → confirm → `deleteTransaction` → 8s `showDeleteNotice` chain, identical in demo (localStorage) and authenticated (Supabase `soft_delete_money_transaction`) modes.
- Changed: `findLedgerDuplicateGroups` buckets by `accountHint|kind|amount|normalizeDesc(normalizeSearchText(note))` — the `đ→d` fold from search-text covers what NFD cannot reach. Same-day pairs (identical fingerprint) always flag, including empty notes; near-day pairs need a non-empty note and a non-habitual bucket (≥4 occurrences at ≤2-day median gap suppress the "Cà phê 30k daily" cadence); a lone 2-day-edge pair needs a ≥3-row cluster. Transfers, `isRecurringPayment` rows and `pending:*` optimistic rows are excluded. In a habitual bucket only the colliding same-day rows emit a group. Dismissal keys hash the bucket (pattern-level), so a dismissed combination stays quiet as rows join — and a genuinely new duplicate of a dismissed combination stays suppressed (documented trade-off).
- Verified: typecheck, lint (1 pre-existing warning in unrelated quick-add-defaults.test.ts), 1617/1617 unit tests (+16 detection, +5 dismissal), build (51 routes), check:knowledge, test:ci-policy (191/191), check:architecture, check:css-ownership. `agent:doctor` reported the three `NEXT_PUBLIC_*` env vars absent from the process environment (`.env.local` exists; env readiness ≠ gate result). Local `node_modules` symlink replaced with a hardlinked copy — Turbopack refuses out-of-root symlinks; environment fix only. Browser smoke and cross-device audit delegated to CI lanes.
- Remaining: a real double-entry inside an established habit only flags if it lands on the same day (near-day flags are suppressed there); fresh habits can flag once before a cadence is provable — the intended review-then-dismiss path. Dismissal is device-local; a second device re-surfaces dismissed patterns.
- Production/provider evidence: none (no migration; production verification remains an owner decision post-merge).
- Superseded issue, roadmap or claim: none.
- Lifecycle impact: if the strip proves noisy or misses real dupes, revisit the habit thresholds (`LEDGER_DUPE_HABIT_MIN_OCCURRENCES`, median-gap bound) or per-cluster dismissal keys; if a "trùng?" filter chip is wanted, the transaction filter model would need a new axis — intentionally skipped as not cheap.
