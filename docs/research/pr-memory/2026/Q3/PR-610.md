## Boundaries

- Bearer honoring lives in `createClient()` (decision D1a): a valid Supabase JWT is authentication everywhere, so loaders needed no changes and there is exactly one data path. A page request carrying an Authorization header renders as that token's user — documented as intended uniform semantics.
- Cookie sessions still work on the route (uniform auth); CSRF surface is bounded by SameSite cookies + JSON content-type.
- Demo viewers are explicitly rejected — demo data is never an authenticated identity.
- `getClaims(jwt)` (JWKS-local or `getUser` fallback) is the verification; no token material is logged or returned.
