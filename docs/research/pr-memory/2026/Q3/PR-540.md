## Share Target regression and review

The patched runtime's first full browser smoke passed 134/136; both failures were the same `/capture/share` loading/redirect case. The original effect consumed `ranRef` before `requestAnimationFrame`, so React Strict Mode setup -> cleanup -> setup could cancel the first frame after the one-shot was already spent.

The first repair moved the one-shot into the RAF callback. Independent review then found that removing RAF cleanup allowed abandoned work after unmount/navigation. Commit `91a93c3e80474f37f52f90405a91190d36b093e4` keeps both guarantees: cleanup cancels the scheduled frame, and `ranRef` is consumed only by a frame that actually executes. Hard navigation remains intentional; existing browser assertions were not weakened.
