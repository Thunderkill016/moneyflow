## Live Supabase advisor reconciliation

Read-only provider evidence was refreshed after the dependency work. MoneyFlow remains `ACTIVE_HEALTHY`. Security Advisor continues to report authenticated-callable `SECURITY DEFINER` warnings across intentional ledger/planning/reconciliation/import/archive RPC surfaces and separately reports leaked-password protection disabled.

A read-only catalog reconciliation checked every currently warned authenticated-callable `SECURITY DEFINER` function. Across that set, `anon` has no `EXECUTE`, `PUBLIC` has no `EXECUTE`, `authenticated` does have `EXECUTE`, the owner is `postgres`, the function config is `search_path=''`, and the body references `auth.uid()`. This materially narrows the warning: it is not an accidental public/anonymous function grant and not a missing hardened search path, but it remains a privileged authenticated RPC surface that must enforce tenant ownership correctly in each body.

The highest-obvious identity-parameter case, `reconciliation_snapshot_for_user(p_user_id, ...)`, explicitly rejects a caller when `p_user_id is distinct from auth.uid()` and then constrains the account query to the authenticated user. Representative mutation functions inspected live (`create_money_transaction`, `bulk_update_transaction_category`, `approve_inbox_candidate`, `restore_user_archive`) derive `v_user_id := auth.uid()` and bind row reads/writes to that value; the archive restore also validates the archive contract before domain writes. This is evidence that the lint class is largely intentional per-user privilege elevation, not evidence that every function is already fully dispositioned. Remaining functions still require the packet's source/test classification before suppression or any privilege change.

Supabase's current lint documentation explicitly recognizes intentional per-user privileged operations as a valid reason to keep both `SECURITY DEFINER` and authenticated `EXECUTE`, provided inputs and effects are constrained. It also confirms `SECURITY DEFINER` functions should harden `search_path`; the live functions satisfy that configuration requirement.

No `SECURITY DEFINER` function was converted, moved or revoked in this dependency PR.
