# PR #482 — fix(deps): raise the postcss override to a patched release

- Date: 2026-08-26
- Change class: Class 1 — bounded dependency-graph change plus the security test that guards it. No application code, schema, migration, RPC, RLS, provider or financial-semantics change.
- Affected capability or project boundary: the build-time dependency graph in `package.json`/`package-lock.json` and `src/lib/dependency-security.test.ts`.
- Status impact: candidate until merged. It closes two open Dependabot alerts; no capability changes.
- Lifecycle impact: completes current slice. Issue #418 is delivered in this same PR, which carries its own post-merge convergence: the board projection names PR #482, no successor slice is promoted, and projected current memory is updated here. `plan:resolve` intentionally reports NOT READY while this is unmerged.
- Provenance recovered first, which is what #418 required before any change: the override arrived in `158a9d69` "fix: update Next.js security release", whose squashed commits include "fix: override vulnerable Next transitive dependencies" and "test: target actual PostCSS and Sharp packages". It was pinning a patched release at the time, not an arbitrary version.
- That reason still holds, verified rather than assumed. Removing the override was tried first: `npm install --package-lock-only` then resolves `node_modules/next/node_modules/postcss` at **8.4.31**, far below the patched floor. So the override is load-bearing and must stay — it exists to stop Next resolving its own nested copy.
- The defect: the override pinned `postcss` at `8.5.19`, so `nanoid` resolved to `3.3.16`. Both carry advisories — nanoid needs ≥ `3.3.18` (high, custom generators can loop indefinitely) and postcss needs ≥ `8.5.23` (moderate, incomplete fix of GHSA-6g55-p6wh-862q). The repository's own pin was holding the fix out.
- Changed: the override moves to `postcss 8.5.26`, with an explicit `nanoid 3.3.18` override rather than trusting whatever range postcss allows. After `npm install`, a full walk of the lockfile confirms no `postcss` below 8.5.23 and no `nanoid` below 3.3.18 anywhere in the tree, nested copies included.
- The security test had the wrong shape, and that shape is why the alerts stayed open: it asserted `postcss` equals `8.5.19` exactly, so raising the dependency to the fixed release made the **security test fail**. A guard that must be weakened in order to apply a security fix is inverted. `postcss` and `nanoid` are now asserted as a patched floor across the whole lockfile; `next` and `sharp` keep exact pins, since neither was involved and pinning the framework release is deliberate.
- The new floor was proven non-vacuous rather than assumed: lowering `node_modules/postcss` in the lockfile back to `8.5.19` and re-running the test makes it fail, and the lockfile was restored afterwards.
- Verified: `npm ci` clean, `npm run build` with `NEXT_PUBLIC_APP_MODE=authenticated` succeeds and still emits 22 CSS files — postcss is build-critical, so a passing unit suite alone would not have been evidence. `test` (**1173 pass**), `lint`, `typecheck`, `check:architecture`, `check:css-ownership`, `check:code-css-ownership`, `check:knowledge`, `test:ci-policy`, `check:migrations`.
