# PR-636 — Capture V2 Slice 0 benchmark harness

**Status:** open at authoring time; CI pending.
**Branch:** `feat/capture-bench-harness`

## What shipped

`public/capture-bench.html` — a self-contained, noindex TTLT benchmark for the
existing capture surfaces, plus `src/lib/capture-bench-tool-contract.test.ts`
and the bounded packet `docs/plans/active/capture-v2-benchmark-harness.md`.

## Why this shape

- The Capture V2 spec's Slice 0 requires TTLT/taps/correction evidence for the
  released amount-first Ghi flow *before* any UI change is justified.
- `frame-ancestors 'none'` blocks iframe embedding, so measurement runs
  two-tab: harness page holds the timer, the app runs in a sibling tab, and
  `storage` events on `moneyflow-demo-transactions-v1` /
  `moneyflow-inbox-candidates-v1` auto-stop timing when a commit lands.
- No product code was touched; the tool is observation-only and writes nothing.

## Honest limits

- Tab-switch latency (~1–3 s) is inside every number; use for relative
  mode-to-mode comparison, not absolute claims.
- Demo fixtures are a stable-history cohort only; a true first-time cohort
  still needs a fresh-profile run.
- Correction auto-detection works in demo mode only (same-id localStorage
  rewrite within 60 s).

Lifecycle impact: adds Slice 0 measurement tooling; does not authorize or
