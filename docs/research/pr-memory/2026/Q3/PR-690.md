# PR #690 — Past-month plan-vs-actual review strip on /budgets

- Date: 2026-09-23
- Change class: Class 2 (bounded UI surface on one planning page; one additive server read mirroring the existing `monthIncome` query — no migration, schema, RPC or provider change)
- Affected capability or project boundary: `/budgets` presentation (`src/components/planning/budgets-page.tsx` + `planning-workspace.module.css`), `BudgetsWorkspace` in `src/server/budgets.ts`, new pure module `src/lib/planning/month-review.ts`.
- Status impact: PRODUCT_METRICS §8.2 asks plan-versus-actual with legible cause attribution; the budgets page could navigate to a finished month but never stated how it closed. Now a strictly-past month gets a compact "Tổng kết" strip — Thu / Chi / Ròng from recorded ledger facts, `n/N hạn mức trong giới hạn`, `m/M khoản định kỳ đã trả`.
- Changed: `buildMonthReview` returns `null` unless `monthStart` fully precedes the server-resolved `today` month, so the current month keeps the pace UI untouched. Each segment is independently nullable — a month with no budgets or no due commitments withholds that segment instead of printing `0/0`. "Trong giới hạn" closes against the effective limit (`budgetRollover` carry folded in) so the strip cannot disagree with the cards below it. New `monthExpense` field is the `kind="expense"` twin of the `monthIncome` read on `transaction_feed` (whole-month window); it was required for honesty because `budget_progress` only covers budgeted categories, so budget-derived "Chi" would have dropped unbudgeted spending and fabricated `Ròng`. Strip renders as a semantic `dl` after the summary grid, gated on `!dataError`, derived from live `budgets` state so past-month limit edits re-count immediately.
- Verified: `npm run typecheck` clean, `npm run lint` 0 errors (1 pre-existing warning in untouched `quick-add-defaults.test.ts`), `npm run test` 1721/1721 (12 new), `npm run build` clean, `check:knowledge`, `test:ci-policy` 191/191, `check:css-ownership`, `check:architecture`. Dev-server smoke in demo mode: strip renders on `?month=2026-08` (commitment segment correctly withheld — demo seeds none), absent on the current month. Browser/visual audit delegated to CI lanes.
- Remaining: archived commitments are excluded from `m/M` (codebase convention; no archived-at timestamp exists to prove the obligation was live that month). Demo past months show Thu/Chi = 0 because the demo ledger only seeds rows near today. Goal-funding attribution intentionally absent — the allocations read lands in a parallel PR.
- Production/provider evidence: none (additive read inside existing RLS + `user_id` filter; production verification remains an owner decision post-merge).
- Superseded issue, roadmap or claim: none.
