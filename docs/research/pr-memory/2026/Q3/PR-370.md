## Why this exists

The owner rejected every Phase E territory. Rather than propose another direction, this
improves what actually ships. It is explicitly not Brand v3, not Design System v3, and it
does not complete Phase E.

## What the evaluator caught, and why it mattered

It ran the app rather than reading the CSS, which is the only reason three of these were
found:

- **The "one workspace" claim was false.** Summary and manager are grid siblings, so the
  18px workspace gap reopened the seam they were meant to close — leaving a card with no
  bottom edge, visible in light and dark on the flagship screen. Fixed by tying a negative
  offset to the gap variable so the two cannot drift.
- **The disclosure closed itself under the user's hands.** `open` derived straight from
  the filter state auto-*closed* when a filter was cleared, taking focus off the control
  being operated. It now latches: seeded from the initial filter state — the browser fires
  no toggle for a panel already open on mount — and carried by `onToggle` thereafter. All
  four cases verified in the browser.
- **I shipped a new 40px control while the commit message asserted no new sub-44px
  targets.** The disclosure summary is now 44px, and the claim was wrong when written.
- **The headline number was quoted selectively.** Mobile toolbar 777→267px was true only
  unfiltered; the open state was 827px, *worse* than main. Two-up filter grids brought
  that to 641px, and the packet now tabulates all four states — including desktop-filtered
  at 369px against main's 261px, which is a real regression traded for wins elsewhere.
- **Dark mode inverted the mechanism it claimed.** `--mf-surface-muted` is brighter than
  the manager surface in dark, so the filter band advanced instead of receding. Changed to
  `--mf-canvas`, which sits below the card in both themes; measured luminance 0.954 vs
  1.000 light and 0.0057 vs 0.0092 dark.
