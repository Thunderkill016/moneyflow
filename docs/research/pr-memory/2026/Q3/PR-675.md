# PR #675 — Net-worth balance-over-time series on /reports

- Date: 2026-09-22
- Change class: Class 2 (bounded UI/flow — one new section on /reports over existing read paths; touches a financial read, so the heavier money rules were held)
- Affected capability or project boundary: `src/lib/balance-series.ts` (new pure replay-ledger module + tests), `src/server/reports.ts` (`ReportsWorkspace.balanceSeries`, feed read loses its upper bound, parallel `accounts` + `account_balances` reads), `src/components/reports-page.tsx` + `.module.css` ("Tài sản ròng" section), `src/server/capabilities/capability-test-helpers.test.ts` (fixture gains the field).
- Status impact: /reports now shows balance over time — a capability Actual/YNAB-class products carry — without adding a balance-history table. The ledger stays the single source; the past is reconstructed, never stored.
- Changed: net-worth series is derived by replaying backwards from the current `account_balances` anchor (value at bucket end = current balance − Σ entries dated later), so no balance is ever invented. All math stays integer minor units; unsafe totals or malformed account rows degrade the section to an empty state instead of breaking the report. Transfers post −/+ legs exactly as `transaction_entries` does — they move account series but net to zero. Net worth sums VND accounts only; FX accounts keep per-currency series labelled "ngoài tài sản ròng", and an FX-only ledger reports `netWorthVnd: null` rather than a fake zero. Bucketing follows the same span rule as the spending trend (daily ≤ 62 days, else calendar months). The feed query dropped `.lte(currentEnd)` because the anchor already contains future-dated entries — capping would have inflated every reconstructed point.
- Verified: typecheck, lint (0 errors, 1 pre-existing warning), npm test 1540/1540 (15 new balance-series tests), build 51 routes, check:knowledge, test:ci-policy 191/191, check:architecture, check:css-ownership. Merged origin/main cleanly first (incl. #670 trend-granularity fix, #671 budgets carryover, #672 diacritic search).
- Remaining: the section is read-only reconstruction — no stored snapshots, so very old ledgers still anchor on today's balance (correct by construction, but a long ledger pays for more feed rows on far-past custom ranges). Per-account series are listed as end-of-period rows, not charted lines. CI browser/responsive lanes are the remaining evidence layer.
- Production/provider evidence: none (pure read-path change; no migration, no provider writes).
- Superseded issue, roadmap or claim: none.
- Lifecycle impact: if a real balance-history/snapshot table ever ships (e.g. for reconciliation checkpoints), this replay can become a fallback for pre-snapshot ranges; keep the single-anchor semantics as the contract either way.
