## What this slice proves

The canonical authenticated fixture contains two VND accounts, one income, one
expense and one internal transfer. The browser contract drives the real login
and `/dashboard`, requires the healthy `get_dashboard_bundle` path to be served,
and checks independent literal outcomes:

- total balance `2,700,000` VND;
- period income `2,000,000` VND;
- period expense `300,000` VND;
- period net `1,700,000` VND;
- transfer `500,000` VND remains visible with transfer semantics but does not
  enter income, expense or net.

Expected totals are not calculated by importing the production dashboard
summarizer or production money formatter. The clean authenticated run executed
this contract as authenticated-phone test #6 and it passed.

## Evidence boundary

This is an application/browser composition harness. It proves the real
authenticated Next.js/Supabase-client route, server mapping, dashboard
composition and rendered semantic outcome against a strict synthetic HTTP
double. It does **not** prove PostgreSQL, RLS, tenant isolation, SQL/RPC bodies,
provider settings or production behavior; those remain owned by pgTAP/provider
and production evidence.

The strict double still returns `501` for unimplemented requests and records a
miss. The browser contract requires the miss ledger to stay empty, so a missing
server query cannot silently degrade into empty financial data. It also requires
`/rest/v1/rpc/get_dashboard_bundle` to appear in the served ledger, so a fallback
read cannot accidentally certify the healthy bundled path.

## Research decision

The repository already owns an authenticated harness, CI classifier and
repository-backed agent workflow. Focused research supported strengthening
deterministic environment/outcome feedback, not building another `mf` CLI or
agent platform. The selected slice therefore extends the existing harness and
adds no dependency, runtime or management layer.

The finance side of the research selected only invariants that fit MoneyFlow's
current product law: internal transfers are movements between owned accounts and
must not distort income/expense reporting; reconciliation remains a separate
external-statement proof boundary and was not expanded in this PR.
