# PR #794 — mobile UX end-to-end: welcome intro, auth lifecycle, delete-confirm fix

- Date: 2026-10-15.
- Change class: Class 2/3 — bounded UI/flow polish across the mobile
  surface plus authentication-boundary lifecycle fixes.
- Affected capability or project boundary: `mobile/` Flutter auth
  scaffolding and OAuth return path, Android manifest/activity, delete
  confirmation on both mobile and web, and the web mobile landing/auth/
  onboarding layer. No ledger, schema or data-path change.
- Status impact: implemented and locally verified (lint, typecheck,
  2180 web tests, Flutter tests, on-device OAuth round-trip); not
  merged, not deployed.
- Why: the Google Custom Tab callback could create a second
  MainActivity (`singleTop` reuses only when on top), disposing the
  waiting `_AuthGate` and leaving users on login despite a successful
  `/get-session` exchange; the resurrected intent also pushed a
  duplicate login route over the dashboard via Flutter deep-linking.
  Separately, Vietnamese keyboards emit decomposed Unicode or users
  type `XOÁ`, so the byte-exact `XÓA` confirmation never matched.
- Changed: `AndroidManifest.xml` → `singleTask`; `MainActivity.kt`
  swallows `moneyflow://oauth-callback` before `super.onNewIntent`
  forwards it to the Navigator; `app.dart` guards `setState` behind
  `mounted` in `_restore`/`_restoreOffline`. `matchesDeleteConfirm`
  (mobile) and `isDeleteConfirmValid` (web) fold diacritics to ASCII
  and accept `XÓA`/`XOÁ`/`xóa`/`xoa` while rejecting anything beyond a
  deliberate confirmation word. Flutter gains `AuthScaffold`,
  register/forgot-password pages, `GoogleMark`, `BrandMark`. Web gains
  `mobile-welcome` (≤760px, BrandLockup + one headline + "Tạo sổ" CTA +
  three-slide swipeable carousel with dots and "Bỏ qua"; desktop
  landing untouched) and `install-nudge` ("Thêm MoneyFlow vào màn hình
  chính", dismissible, persisted in localStorage). `auth-form` inputs
  ≥44px with contained captcha; `onboarding-flow` CTA pins sticky above
  `env(safe-area-inset-bottom)`; manifest keeps `display: standalone`
  and brand `theme_color`.
- Evidence: `npm run lint` (0 errors), `npm run typecheck` (clean),
  `npm run test` (2180/2180 pass), `flutter test` (all pass, incl. 17
  delete-related), debug APK installed — OAuth callback returns to the
  live activity and the gate flips to dashboard without a stray login
  route.
- Boundary note: Neon managed auth swallows `prompt`/`loginHint`/
  `scopes`/`additionalParams` on every probe path and ignores
  `idToken` payloads (`/one-tap/callback` is 404), so an always-on
  account picker is provider-blocked; Google still shows its chooser
  when multiple on-device accounts exist. Custom scheme
  `moneyflow://` is not a trusted callback — only the localhost
  loopback is admitted.
