# PR-792 — per-account data freshness on the accounts page

- **PR:** https://github.com/Thunderkill016/moneyflow/pull/792
- **Branch:** `feat/mobile-data-freshness` → `main`
- **Change class:** Class 2 — bounded UI surface addition, no data
  mutation, no schema change.

## What landed

Each account row on `mobile/lib/features/accounts/accounts_page.dart`
now shows a freshness line: `Dữ liệu đến dd/MM/yyyy` (latest
`occurred_on`) or `Chưa có giao dịch`. Both real and demo surfaces wire
`latestActivityFor` through the newest-first `TransactionPageLoader`
(`TransactionQuery(accountId: …)` → row 0).

Honesty contract: the line is absent while the lookup runs, dropped
silently on lookup failure, and hidden entirely when the callback is
omitted. One failing account lookup never blanks the column.

- Superseded issue, roadmap or claim: the 19-app research hypothesis
  "biết phần nào của bức tranh đã đầy đủ"
  (`docs/research/mf-market-research/19-app-lessons-2026-10.md`) is now
  partially testable — the accounts page shows per-source data recency,
  which is the app's only honest freshness signal until provider
  coverage metadata exists.

## Verification

- `flutter analyze`: no issues.
- `flutter test`: full suite green (1030) including 3 new freshness
  widget cases (date shown, "Chưa có giao dịch", silent-while-loading).

## Not verified

- Physical-device rendering; hosted Neon round-trip.
- Freshness only reflects ledger rows the app can see — it cannot prove
  a bank source is complete or current (per the research's own caveat
  that "synced" ≠ "complete").
