# PR #791 — Mobile voice capture + read-only timeline

- Date: 2026-10-14.
- Change class: Class 2 — bounded UI/flow on the existing mobile client;
  one new runtime permission (RECORD_AUDIO, mic-tap scoped).
- Affected capability or project boundary: `mobile/` Flutter app —
  capture flow gains a voice entry; the ledger gains a read-only
  reviewed-only timeline view. No server, migration or web changes.
- Status impact: implemented and locally verified; not merged, not
  deployed. Device-level speech recognition not yet exercised on a
  physical handset (engine is behind an injectable `VoiceEngine` seam).
- Changed: ported `vi-money-parser.ts` → `lib/domain/voice_money_parser.dart`
  (same normalize/slang/span/shorthand algorithm; internal values float
  through `double` so "2,5 triệu" parses 2_500_000); `VoiceEngine`
  seam + `SpeechToTextEngine` (speech_to_text 7.4.0 — 7.5.x needs Dart
  ≥3.12 vs pinned 3.10.4); `voice_capture_page.dart` (mic → listen →
  mandatory confirm → `CaptureIntent` via the existing submit/offline
  queue, per-capture idempotency key); `domain/timeline.dart` +
  `timeline_page.dart` (reviewed-only day groups, net-per-day, summary
  chips, `TransactionQuery` search); manifest gains RECORD_AUDIO +
  RecognitionService queries; capture appbar gains the mic action;
  dashboard menu gains "Dòng thời gian" in real and demo shells.
- Verified: `flutter analyze` clean; `flutter test` full suite green —
  74 parser cases mirror the web contract, plus widget tests for the
  confirm gate (no write without the explicit save tap), unsupported
  device fallback, and timeline grouping/filter/read-only rendering.
- Deliberate cut: no inbox-candidate mirror after a voice save — the
  web's `addCandidatesForClient` relies on `create_inbox_candidates`,
  which is still unapplied on the hosted Data API (PGRST202).
- Remaining: physical-device mic/permission behavior unverified; demo
  voice confirm correctly hits the read-only DemoReadOnly answer;
  merge is the owner decision.
- Production/provider evidence: none — no production data, deploys or
  provider writes; RECORD_AUDIO is a user-granted runtime permission,
  not a provider write.
