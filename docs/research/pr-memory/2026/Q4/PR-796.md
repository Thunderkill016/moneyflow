# PR #796 — mobile dashboard pace/category/upcoming + web attention parity + account nav

- Date: 2026-10-17.
- Change class: Class 2 — bounded dashboard/surface UI on mobile plus a
  matching web attention-rule extension; no schema, ledger or auth
  boundary change.
- Affected capability or project boundary: `mobile/` dashboard feature
  surface and account register; `src/lib/` web attention aggregation.
  No migrations, no RPC contract change.
- Status impact: implemented and locally verified (Flutter analyzer 0
  issues, focused + full test runs green, on-device screenshots in
  demo mode); not merged, not deployed.
- Why: research (`docs/research/DASHBOARD_PATTERNS_TOP_APPS_2026.md`)
  showed the top apps all answer "am I on pace this month" visually —
  Copilot's cumulative-vs-ideal line, Spendee's per-category bars,
  Monarch's upcoming-bill strip. The dashboard only carried raw
  month-to-date numbers. Separately, wallet cards looked tappable but
  did nothing, and the register had no close/reopen action (the
  Monarch close contract already existed on the accounts row).
- Changed: web `buildFinancialReport` carries the same per-bucket MoM
  column — `categories[].previous` and `payees[].previous` from the
  identical prior-window read (split/refund/trim rules matching the
  current buckets), prior-only buckets kept as honest zero rows; the
  reports page renders the mobile ▲/▼/"mới"/"Không đổi" contract.
- Changed: `report.dart` gains `expensePayeeDeltas` — the payee MoM
  column for "Chi theo người nhận" (Money Lover Insider pattern),
  bucketing on trimmed payee text verbatim like `payeeIds`, refund
  netting, excluded-skip and the unnamed bucket all matching the
  breakdown; `_expenseBuckets` also gained the `excludedFromReports`
  skip so a hidden row can never invent a delta its breakdown row
  doesn't show. `ReportsPage` passes `payeeDeltas` into the existing
  `_ShareSection` delta slot from the same prior-window read — no
  extra fetch.
- Changed: `month_pace.dart` gains `buildMonthPace` — pure domain math
  for cumulative spend vs ideal pace; `_MonthRemainderCard` renders
  `_PaceChart` (CustomPainter: cumulative line vs dotted ideal, day
  marker, "Đúng/Nhanh hơn/Chậm hơn nhịp" status chip) when the summary
  read is trustworthy. `MonthSummary` gains `topCategories`; the
  summary card shows three share bars ("Hóa đơn 52% · 1.2tr"). The
  attention card surfaces commitments due within 7 days as "sắp đến
  hạn", keeping overdue and paid-different separate — the same rule
  now applied to the web `buildAttentionItems` (upcoming + paidAmount
  join). Dashboard wallet cards gain `onOpenAccount` →
  `AccountRegisterPage` (InkWell + honest chevron only when the seam
  exists); the register gains `onArchiveAccount` → appbar menu with
  "Đóng tài khoản" (confirmation dialog: hidden from pickers, history
  kept, reopenable) and "Mở lại tài khoản" (immediate), a local
  `_closed` flag for the "Đã đóng" chip, and read-only honesty when
  the seam is absent (demo). `MF_ALLOW_CAPTURE` /
  `MF_ALLOW_DEMO` dart-defines gate QA screenshot and demo entry;
  shipped builds keep FLAG_SECURE and no demo path.
- Evidence: `flutter analyze` 0 issues; focused suites green
  (dashboard 73 tests incl. pace/upcoming/no-chevron cases,
  account_register 52 incl. close-confirm-write/reopen-menu/no-seam
  cases); `flutter test` full run green after watchlist assertion
  fix (share bar and watch row legitimately both render "Ăn uống");
  web `attention.test.ts` 18/18; debug APK built and dashboard
  screenshots captured on OPPO CPH2001 under the QA capture gate
  (docs/design/dashboard-pace-v3/).
- Boundary note: `MF_ALLOW_CAPTURE` and `MF_ALLOW_DEMO` default off —
  production builds keep screen protection and hide the demo entry;
  the web attention change reuses the existing recurring feed (no new
  provider read). Demo registers intentionally receive no archive
  seam.
- Follow-up slice (report parity): `expensePayeeDeltas` on mobile +
  `previous` on web category/payee buckets — the same bucketing,
  refund-netting, exclusion and trimmed-payee rules as the primary
  report; prior-only buckets stay as zero-current rows; a missing
  baseline renders "mới", never a fake zero. Mobile `_expenseBuckets`
  was corrected to skip `excludedFromReports` so the comparison and
  the breakdown can never diverge. Web `bucketDelta` renders
  ▲/▼/"mới"/"Không đổi" under each category and payee row.
- Follow-up slice (treemap, Monarch #19): `mobile/lib/domain/
  treemap.dart` squarified layout + `_CategoryTreemap` above the
  expense-category rows — top-7 pastel blocks plus a non-drilling
  "Khác" roll-up; cells tap into the same filtered feed as rows.
- CI repair on this head: `audit_gaps_test` 2x-text-scale overflow —
  account-card kind chip now Flexible+ellipsis so the chevron is
  never pushed off; `reports.financial` golden updated for the new
  `previous` field (capability spreads `...category`, so the field
  legitimately flows through — the golden caught the contract drift
  exactly as designed).

  writing — see the PR check list for exact-head results.

- Production/provider evidence: none — UI/domain-only change; the
