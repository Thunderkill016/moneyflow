# PR-764 — feat(voice): replace Vosk with Web Speech API for instant Vietnamese capture

- **PR:** https://github.com/Thunderkill016/moneyflow/pull/764
- **Branch:** `feat/voice-web-speech` → `main`
- **Date:** 2026-10-06
- **Context:** PR #763 (Groq Whisper) was closed unmerged per Hoàng's decision: "ko dùng grok dùng web speech đi" — no signup, no API key, instant.
- **Why Web Speech:** Hoàng reported the Vosk 33MB model wouldn't download on his device. Web Speech API is built into the browser: zero download, zero signup, zero server. Trade-off accepted by Hoàng: recognition quality depends on the browser vendor (worse than Vosk/Whisper for Vietnamese), and short audio clips leave the device (stated plainly in UI + privacy policy).

## What changed
- New `src/lib/voice/web-speech-engine.ts`: `SpeechRecognition`/`webkitSpeechRecognition`, `lang=vi-VN`, `interimResults=true`, Vietnamese error messages (not-allowed / no-speech / network), abort + maxSeconds support, `ensureVoiceModel`/`releaseVoiceModel` no-op shims for caller compatibility.
- `src/hooks/use-voice-capture.ts`: uses web-speech engine, restores live `partial` transcript, `loading-model` phase renamed `preparing`.
- `src/components/voice/voice-capture-page.tsx`: preparing UI (no download), privacy line now says audio is transcribed by the browser and deleted immediately.
- `src/components/privacy-policy-page.tsx`: voice section rewritten (no on-device claim, no model download).
- Deleted: `src/lib/voice/vosk-engine.ts`, `scripts/fetch-voice-model.mjs`, `prebuild` hook; `dev` script restored to plain `next dev`.
- `vosk-browser` intentionally KEPT in package.json: package-lock.json (~380KB) can't be pushed via GitHub API; remove in a separate PR with a proper git push.

## API-push lesson (2026-10-06, important)
`create_or_update_file` via GitHub MCP:
- For EXISTING files, the `sha` parameter is REQUIRED — without it the call returns ok:true but silently does nothing.
- `content` is written LITERALLY — it does NOT base64-decode. Pass raw text, never base64.
- First push of this PR wrote new files as literal base64 (ESLint parse errors at 1:8803) and silently skipped updates to existing files → CI failed 6 checks. Fixed by re-pushing with sha + raw text.
