# Security Policy

## Supported version

Security fixes target the current `main` branch and the production deployment built from it.

## Reporting a vulnerability

Use GitHub's **Security** tab and select **Report a vulnerability** so the report is handled privately.

Do not disclose suspected vulnerabilities, credentials, personal data, provider identifiers, exact abuse thresholds, or reproduction details in a public issue, discussion, pull request, or commit.

If private vulnerability reporting is unavailable, contact the repository owner through their GitHub profile and request a private reporting channel without including sensitive details in the first message.

Include:

- affected component and impact;
- minimal reproduction steps;
- whether exploitation was tested against production;
- suggested mitigation, if known;
- any credential or personal-data exposure.

Do not access, modify, retain, or publish another person's financial data. Stop testing once the issue is demonstrated.

## Response

The maintainer will acknowledge a valid private report, assess severity, coordinate a fix, and publish only the minimum safe disclosure after remediation. Exact timelines depend on severity and verification needs.
